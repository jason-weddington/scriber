# Scriber design

Scriber is a macOS dictation app built on Rust, Tauri 2 and Svelte 5. This file is its spec and the bridge contract between the webview and the Rust core. Change it in the same commit as the behaviour it describes, and when reality disagrees with it, fix whichever one is wrong.

## What it does

The user dictates long instructions to paste into another app (typically a Claude Code session). They click **New** to start a session, **Record**, talk, **Pause**, think, **Resume**, talk more, as many times as they like, then **Done**, or do all of it from the keyboard (⌘N, Space, Return), and ⌘, opens Settings. While recording, a waveform below the buttons shows that the microphone is picking them up. After a brief transcription step the transcript is shown in an editable box and is already on the clipboard, paste-ready. Every finished dictation is also kept in a recording library, a drawer on the left of the window, titled by when it started and summarized in one sentence by a local model (Ollama) when one is running. Transcription is fully local (whisper.cpp on Metal); the only network use is downloading the speech model once, when it is missing, and asking the local Ollama server (127.0.0.1) for summaries and, when the user turns it on, a cleanup pass over each transcript. There is no file watcher, no speaker labels and no cloud; a global toggle (⌥⌘D by default) works from any app. Small transcription errors are acceptable; the reader has context to absorb them.

The rules, each enforced by `scripts/check-architecture.sh` and proven by `scripts/selftest-checks.sh`:

- The core's dependency tree has no Tauri, no webview and no async runtime, and its code reads no file, clock, environment or network directly. Every effect goes through a trait in `ports.rs`; the real implementation lives in `crates/scriber-engine` (the clipboard's in `src-tauri`), the fake in the core's tests.
- The engine's dependency tree has no Tauri, no webview and no async runtime either, so none reaches an app that depends on it.
- `src-tauri` holds `lib.rs` and `main.rs` only, `lib.rs` stays under 400 lines, and it has no tests. Logic that needs a test belongs in the core, and an adapter any app could use in the engine.
- `src/lib/bridge.ts` is the only frontend file that imports `@tauri-apps/*` (also an eslint rule). Outside Tauri it answers from `src/lib/mock.ts`, and marks `<html data-bridge="mock">`; inside Tauri it marks `data-bridge="tauri"`.
- No `#[allow(...)]` anywhere; a lint exception is `#[expect(lint, reason = "...")]`.

### Ports

| Port | Real adapter | What the core asks of it |
|---|---|---|
| `Recorder` | `scriber-engine` `CpalRecorder` (`device.rs`): cpal, the input device named in the settings (the first whose `description().name()` matches), or the default one for `""`, at its default config (f32); a device name that cannot be read is answered as "Unknown microphone" | `start(device, split_ms)`: start a segment from that device, closing a segment after `split_ms` of silence (the setting `silence_split_ms`; 0 is off) (`""` for the default) and answer the name of the device opened (no match fails with "there is no input device named <name>", no default with "there is no input device"); `inputs()`: the default's name and every other input device's, as `InputDevices::new` orders them; `take_closed()`: hand over the segments the capture closed at a silence, oldest first, without stopping the device (empty when not recording); `on_split(notify)`: keep `notify` and call it on the audio thread, after the tap is unlocked, whenever capture closes a segment; stop and hand over, as one capture, everything not yet handed over (closed segments included), as interleaved samples with their channel count and rate. A split never stops or reopens the device. Each block the device delivers goes to a core `level::Tap` (through `level::feeder`), which keeps it and meters it |
| `Transcriber` | `scriber-engine` `Whisper` (`whisper.rs`): whisper-rs 0.16, with the `metal` feature on macOS only (the CPU elsewhere, so the workspace builds and gates on Linux) | whether the model file is missing; load the model now (`warm`); samples (16 kHz mono) plus an optional prompt to phrases, in order, each its text exactly as the model produced it plus start and end sample offsets (end exclusive) into the audio it was given, which `whisper.rs` converts from Whisper's centisecond segment timestamps with the core's `samples_at` |
| `Files` | `scriber-engine` `DataDir` (`files.rs`): `std::fs` under the data folder the consumer gives | read, write (the folder is created), list a folder (a missing one is created and lists empty), remove, append, rename in one step; paths relative to the data folder |
| `Clipboard` | `src-tauri/src/lib.rs`: `tauri-plugin-clipboard-manager` (another consumer passes its own, or none) | write text |
| `JobQueue` | `scriber-engine` (`lib.rs`): one named std thread (`scriber-job`) per job | take a job (a closed segment, the warm-up, the download) off the UI thread; `dictation::work` runs it and reports each snapshot it changes |
| `Downloader` | `scriber-engine` `HttpDownloader` (`net.rs`): ureq 3 over native-tls (Security.framework, the system's roots) | open a URL, following redirects, as a body to read; an error status is an error |
| `Clock` | `scriber-engine` `LocalClock` (`clock.rs`): `chrono::Local::now()` | the local wall-clock time (year, month, day, hour, minute, second), to title a library entry |
| `Encoder` | `scriber-engine` `Afconvert` (`encode.rs`): runs `/usr/bin/afconvert -f m4af -d aac -b 32000 <in.wav> <out.m4a>` with both paths under the data folder | encode a WAV file as AAC in M4A; a missing binary (every non-macOS host) or a non-zero exit is an error |
| `Summarizer` | `scriber-engine` `Ollama` (`ollama.rs`): ureq 3 POST to `<ollama_url>/api/chat`, 60 s overall timeout; every chat request sends `keep_alive: "10m"` (`KEEP_ALIVE`), so it never shortens the kept-warm model's stay; a reply whose `done_reason` is `length` is an error (the entry keeps its excerpt) | a model name and a transcript to its one-sentence summary, the model's raw `message.content` except that a reply containing `</think>` is cut to the trimmed text after its last `</think>`, and nothing after it is an error (the core cleans it); each call names its model (`""` = the adapter's `summary_model`) |
| `Cleaner` | `scriber-engine` `Ollama` (`ollama.rs`): the same ureq 3 POST to `<ollama_url>/api/chat` with `summary_model`, a 120 s overall timeout (`CLEANUP_TIMEOUT`); every chat request sends `keep_alive: "10m"` (`KEEP_ALIVE`); a reply whose `done_reason` is `length` is an error; the request also sends `format: {"type":"object","properties":{"replacements":{"type":"array","items":{"type":"object","properties":{"from":{"type":"string"},"to":{"type":"string"}},"required":["from","to"]}},"learned":{"type":"array","items":{"type":"string"}},"transcript":{"type":"string"}},"required":["replacements","learned","transcript"]}`, Ollama's structured output, so the model can only answer with those three fields (the prompt names the three fields the schema requires, so the prompt and the constrained decoding agree) | a model name, a system prompt and a request to the reply's `message.content`, parsed as JSON after the `</think>` cut (a reply containing `</think>` is cut to the trimmed text after its last `</think>`, and nothing after it is an error): the `transcript` field verbatim and the `replacements` and `learned` arrays, an absent or unusable array being empty; content that is not JSON, or has no string `transcript`, is an error whose message quotes the reply's first 200 characters (the core judges the reply, `cleanup::accept_reply`); each call names its model (`""` = the adapter's `summary_model`) |
| `Warmer` | engine-only port (`warm.rs`, not in `scriber-core`); `scriber-engine` `Ollama` (`ollama.rs`): ureq 3 POST to `<ollama_url>/api/generate` with `{model, keep_alive: "10m"}` to load within `WARM_TIMEOUT` (60 s), and `{model, keep_alive: 0}` to release within `RELEASE_TIMEOUT` (2 s); any 2xx status is success | `warm(model)` loads the model and keeps it loaded for the keep-alive from now; `release(model)` unloads it now; `""` = the adapter's `summary_model` |

`Clock`, `Encoder` and `Summarizer` are only used with the library on: they travel together in `ports::Library`, which `Ports::with_library` adds; `Ports::new` leaves it `None`. `Cleaner` is not in `ports::Library`: `Ports::with_cleaner` adds it whether or not the library is on (the engine always does), and `Ports::new` leaves it `None`, which never cleans up. The gate never needs Ollama or afconvert: the core's tests fake every port, the Ollama adapter is tested against an in-process HTTP stub, and the afconvert adapter against stub scripts.

The Whisper context loads once and stays loaded (`sync::LoadOnce`). At launch, when the model is installed, the core queues a warm-up job that loads it (about 7 s on an M-series Mac for `large-v3-turbo`, cold), so it is ready by the time the first segment closes; a transcription that arrives while the warm-up is still loading waits for it under the same lock rather than loading a second copy, and a load that fails is tried again by the next transcription, which reports the failure. A failed warm-up changes nothing in the session. Later segments take well under a second each. Decoding is beam search (beam 5), English, with non-speech tokens suppressed. Each job runs on a std thread of its own, and the Whisper lock lets one transcription run at a time; jobs may finish in any order.

## The data folder

The app data folder is `~/Library/Application Support/com.jasonweddington.scriber/` (Tauri's `app_data_dir`); another app using the engine names its own (`EngineConfig::data_dir`). `crates/scriber-core/src/store.rs` owns its layout:

```
vocabulary.txt                   optional glossary, one term per line (the default; settings.json can name another file)
settings.json                    the user's settings: {"summaries": bool, "library_open": bool, "vocabulary": string, "cleanup": bool, "summary_model": string, "cleanup_model": string, "library_width": number, "input_device": string, "silence_split_ms": number, "keep_segments": bool, "learned_vocabulary": string, "model_folder": string, "toggle_shortcut": string}
microphone-log.jsonl             the microphone decision log, newest 200 lines (below)
learned.txt                      optional, the default: terms learned from the user's corrections, one per line, newest first, at most 100 (see Learning); written only by the app; settings.json's learned_vocabulary names another absolute path
learning-log.jsonl               the learning log, newest 200 lines (below)
model-log.jsonl                  how the model's location was decided: each launch, each download outcome, each settings write, newest 200 lines (below)
menubar-log.jsonl                the menu bar's decision log, newest 200 lines (below)
segments/segment-0000.wav        the current session's audio, one file per segment
segments/transcript.txt          the session's transcript, once finished (and after each Copy)
segments/started.txt             the session's start as a title (2026-10-26 14:03:09), with the library on

library/<id>/audio.m4a           its audio as AAC (audio.wav until it is encoded, or when encoding fails)
models/ggml-large-v3-turbo.bin   the speech model; the default, in `settings.json`'s absolute `model_folder` when set
```

The model is ggml `large-v3-turbo` from `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin`, 1,624,555,275 bytes, SHA-256 `1fc70f774d38eb169993ac391eea357ef47c88757ef72ee5943879b7e8e2bc69` (all three pinned in `crates/scriber-core/src/download.rs`).

`microphone-log.jsonl` is how a garbled transcript is traced to its microphone. Every Record or Resume that reaches the microphone adds one compact JSON line, `{"event":"start","started":string|null,"action":"record"|"resume","wanted":string,"opened":string|null,"outcome":"opened"|"fallback"|"failed","first_error":string|null,"second_error":string|null,"mismatch":bool,"split_ms":number}`: `started` is the session's start title (null on a session's first Record, and with the library off), `wanted` the saved `input_device`, `opened` the device the recorder answered, the two errors the two `start` calls' texts, `mismatch` true when a named device opened under another name, and `split_ms` the saved `silence_split_ms` passed to both `start` calls. Every closed segment (a successful stop) adds `{"event":"segment","started":string|null,"device":string|null,"channels":number,"sample_rate":number,"samples":number,"peak":number,"cause":"stop"|"silence","longest_silence_ms":number,"quietest_rms":number}`, the capture as the device delivered it, before resampling; `cause` is "stop" for a segment closed by Pause or Done and "silence" for one closed by the automatic split, and `longest_silence_ms` and `quietest_rms` are `level::silence_profile` over the capture (the longest run of 50 ms windows at or below `TRAILING_SILENCE_RMS`, and the quietest complete window's RMS to 4 places, 0.0 with none) The profile skips every segment's first 200 ms (`level::PROFILE_SKIP_MS`, four windows), including a segment closed by the split, because the first 200 ms after the device opens are digital near-silence that would describe the device rather than the room; a segment of 200 ms or less reads 0 and 0.0, like an empty one.; a segment line's `started` equals the library entry's title. Writing is best effort (read, keep the newest 199 lines, add one, write; an unreadable file counts as empty and a failed write is ignored), so the log never stops a recording. It holds device names and error texts only, never transcript text, is untouched by New, Discard and Retry, and has no bridge surface. On the Mac: `tail -n 20 ~/Library/Application\ Support/com.jasonweddington.scriber/microphone-log.jsonl`, and match a segment's `started` to the entry's title. To check the silence split on the Mac: with `silence_split_ms` 1500, record with two pauses of 2 s or more and no Pause press, then `tail` the log; expect a start line with `"split_ms":1500`, then segment lines with `"cause":"silence"` (each with `longest_silence_ms` >= 1500), then a final `"cause":"stop"` line. A stop line with `longest_silence_ms` >= `split_ms` and `quietest_rms` <= 0.002 would mean a missed split; `quietest_rms` above 0.002 on every line means the room was too loud and the split failed safe. To check the profile skip on the Mac: record 3 s or more in a quiet room, Pause, then tail the log; expect the segment line's `quietest_rms` above 0.0 (room noise, typically 0.001 to 0.02); a segment longer than 200 ms that still reads `quietest_rms` 0.0 means the device's startup near-silence outlasted the skip, or the input is digitally gated, not a quiet room.

`learning-log.jsonl` is how a learned (or not learned) term is traced. Every Copy or accepted cleanup that finds a correction (see Learning) adds one compact JSON line, `{"event":"learn","started":string|null,"path":string,"found":[string],"added":[string],"outcome":"saved"|"capped"|"unreadable"|"nothing_added"|"write_failed","error":string|null}`: `path` is the learned list's path (`store::learned_path`: `learned.txt` for the default, the configured absolute path otherwise), `found` is every qualifying term (for a cleanup, the kept learned-term list), `added` the terms placed at the head of the learned list (`[]` unless `saved`), `capped` means more than 5 qualified (only Copy and Accept can reach it: a cleanup returns no terms when more than 5 qualify), `unreadable` that the learned list is not UTF-8, `nothing_added` that every term was already in the glossary file spelled the same, and `error` the write's reason with `write_failed`. Every Undo that restores the list adds `{"event":"undo","started":string|null,"path":string,"removed":[string],"outcome":"restored"|"write_failed","error":string|null}`. `started` is the session's start title, as in the microphone log. Writing is best effort exactly like the microphone log (newest 200 lines; an unreadable file counts as empty; a failed write is ignored). A Copy that finds nothing writes no line. It has no bridge surface. On the Mac, after configuring `learned_vocabulary` to an absolute path and making a learning Copy, `tail` the log and expect `"path":"/Users/<you>/…"`; a `"path":"learned.txt"` line means the stored value was rejected (it did not start with `/`) or the file is not UTF-8.

`model-log.jsonl` is how the model's location is decided and proven. The core writes one compact line per launch, `{"event":"launch","configured":string,"target":string,"partial":string,"outcome":"download"|"already_installed"}`, and one per download outcome, `{"event":"download","configured":string,"target":string,"partial":string,"outcome":"downloaded"|"failed","error":string|null}`; the engine writes one per settings save, `{"event":"settings","requested":string,"stored":string,"answered":string,"dropped":bool}`. `configured` is the value as read back from `settings.json` (so a relative path is already gone), `target` and `partial` the paths the download used; a core line's `target` is relative for the default, because the `Files` port has no root, while the engine's `settings` line always carries absolute paths. Writing is best effort, keeping the newest 200 lines, like the other logs. On the Mac: `tail -n 20 ~/Library/Application\ Support/com.jasonweddington.scriber/model-log.jsonl`; after choosing a shared folder expect `"configured":"/Users/<you>/Models"` with an absolute `"target"`; a non-empty `configured` without a leading `/` plus a relative `target` means the stored value was rejected; `"dropped":true` means the engine refused the folder the caller sent; a second app's launch ends with `"outcome":"already_installed"` and no download.

`menubar-log.jsonl` is how the menu bar's decisions are traced, one compact JSON line each, tagged by `event`: `toggle` is one press of the global shortcut, `{"event":"toggle","phase":string,"toggle":"record"|"act"|"nothing","action":"done"|"resume"|null,"outcome":"ok"|"nothing"|"refused"|"failed","error":string|null,"phase_after":string}`; `menu` is one tray item, `{"event":"menu","id":string,"phase":string,"outcome":"ok"|"refused"|"failed"|"unknown","error":string|null}`; `shortcut` is one registration attempt, `{"event":"shortcut","trigger":"launch"|"settings","accelerator":string,"outcome":"registered"|"unregistered"|"failed","error":string|null}`; and `notify` is one notification decision, `{"event":"notify","phase":string,"visible":bool,"notice":string|null,"outcome":"shown"|"skipped"|"failed","error":string|null}`. `phase` is `Phase::Display` (idle, ready, recording, paused, transcribing, finished, failed), `phase_after` the phase the snapshot reported after a success and the phase before it otherwise, and `error` the engine's or the plugin's sentence. The lines hold phase names, item ids and error texts only, never transcript text (the privacy line above holds here too). Writing is best effort, keeping the newest 200 lines, like the other logs. On the Mac: `tail -n 20 ~/Library/Application\ Support/com.jasonweddington.scriber/menubar-log.jsonl`; a press while recording shows `"toggle":"act","action":"done"`, a second press while transcribing shows `"toggle":"nothing"`, and a shortcut that fails to register has `"outcome":"failed"` with the plugin's reason, the only place that failure is visible.

When the model is missing at launch the app downloads it (`download.rs`): the body streams, 64 KiB at a time, onto `<the model path>.part` in that same folder (the model path being `models/ggml-large-v3-turbo.bin` unless the setting names another absolute folder; written empty first, so a partial file a crash left starts over; there is no resume), and is renamed to the model's path in one step only once its size and SHA-256 match. A download that fails, is too short or too long, or does not match deletes the partial file, so the transcriber never sees a half-written model. Progress is reported once per whole percent. While it runs, every snapshot carries `download` and Record and Resume are refused ("The speech model is still downloading."). When it fails, `modelError` says "Could not download the speech model: <reason>." and the window offers Retry download (`downloadModel`). Once it succeeds the model warms up and Record turns on, with no notice. If the model goes missing with no download running (deleted while the app is open), `modelError` says "The speech model is missing from <path>." with the same Retry download. `scripts/fetch-model.sh` still downloads it from a terminal (idempotent, `curl -fL`, resumable, checks the same size and SHA-256) and always installs into the default `models/` in the data folder, whatever `model_folder` says; the gate never downloads it.

## The session

### States

`crates/scriber-core/src/dictation.rs`, a pure state machine. An action the current phase does not allow returns `DictationError::Illegal` ("Cannot pause while ready.") and changes nothing; the window does not offer those buttons, except New, which stays in the band, disabled.

| Phase | Legal actions | Meaning |
|---|---|---|
| `idle` | new | launched, no session |
| `ready` | record, discard | an empty session |
| `recording` | pause, done, discard | the microphone is capturing a segment |
| `paused` | resume, done, discard | between segments; earlier segments may still be transcribing |
| `transcribing` | none | Done was clicked; waiting for the last segments (and the cleanup, when on) |
| `finished` | new, discard, copy, accept, undoLearn | the transcript is ready |
| `failed` | new, discard, retry | a segment could not be transcribed |

Transitions: New (idle, finished, failed) and Discard (any phase but idle and transcribing) delete the session's audio, re-read the glossary and give an empty `ready` session; Discard while recording stops the microphone and throws the running segment away. Record (ready) and Resume (paused) start the microphone. Pause closes a segment. Done closes the running segment, if any, and moves to `transcribing`, which becomes `finished` or `failed` as soon as no segment is pending (at once when nothing is) or, with cleanup on and a non-empty transcript, `finished` once the cleanup job answers (see Cleanup). Retry (failed) re-reads each failed segment's WAV and transcribes it again; segments already transcribed are kept.

Download model (`downloadModel`) is not part of the phase table: it is allowed in any phase while the model is missing and not downloading, and refused otherwise ("The speech model is already installed or downloading."). A session with no download source (the model is a local file, `Dictation::launch_local`, or a bare `recover`) refuses it first with "The speech model is a local file, so there is nothing to download."

Decided beyond the brief: Discard is refused while idle (there is no session to discard); Discard deletes the session's audio like New does; Record and Resume are refused while the model is missing or downloading, rather than New.

### Segments

Each Pause (and Done while recording) closes a segment: the captured sound is averaged to mono and resampled to 16 kHz by linear interpolation (`audio::to_mono_16k`), saved as `segments/segment-NNNN.wav` (16 kHz mono 16-bit PCM), and queued as a job, so it transcribes while the user thinks and Done only waits for the last one. A job carries its session number; a result from a session that has since been discarded, or for a segment that is no longer pending, is ignored. The transcript joins the segments' text in recording order, whatever order they finish in, with a blank line between segments (a pause is usually a thought boundary).

The automatic split (off by default) also closes a segment at a sustained pause in speech, so text fills in while the user keeps talking. The setting `silence_split_ms` is 0 (off) or 1000..=10000; the Settings window offers Off, 1.5 s, 2.5 s and 4 s. It is read at each Record and Resume, like `input_device`, so a change made while recording applies from the next Resume. The tap (`level::Splitter`) judges 50 ms windows (`WINDOW_MS`) counted from the segment's first sample: a window is silent when its RMS is at or below `TRAILING_SILENCE_RMS` (0.002, the trim threshold; quiet lav speech sits near 0.007). A segment is cut at the end of the window that completes a run of `silence_split_ms` / 50 (rounded up) consecutive silent windows, but only once the segment has had at least one window above the threshold and is at least `MIN_SPLIT_SEGMENT_MS` (2000 ms) long; a louder window resets the run, and a cut starts the next segment afresh (it needs its own speech and its own run). The cut ends at the window that completes the run; the device is never stopped, and no sample is lost or duplicated: the next segment starts at the following sample, and a Pause, Done or Discard that races a split hands over everything not yet taken as one capture. The engine takes each closed segment into the session (`Dictation::split`), where it becomes a pending segment exactly as a paused one (the same prompt, silent-skip, trim, phantom and hallucination rules; `recorded_ms` and `segments` advance as with Pause plus Resume) while the phase stays recording; its text appears in `partial` when it lands. The split fails safe: a room louder than the threshold never qualifies, so it never splits and behaviour is as without it.

The recorded time is the length of the audio of the closed segments (`recordedMs`); while recording, the window adds the running segment's time from its own clock. When a snapshot arrives while recording with a larger `recordedMs` (a part closed at a silence), the window moves its running start forward by the time that moved into `recordedMs`, so the shown time stays continuous instead of counting the closed part twice.

`snapshot.partial` is the transcript so far: the texts of the segments that have been transcribed, joined in recording order with a blank line (as Done joins them), skipping segments still pending, failed or silent. It is raw Whisper output: cleanup, the shortcut glyphs and the learned spellings apply only at finish. It is recomputed for every snapshot, including the state event published when a segment's transcription lands, in every phase (recording, paused, transcribing, failed, finished), so it grows by a whole segment at a time, in recording order whatever the order the outcomes arrive in. New and Discard clear it, and it is empty after a relaunch. `text` keeps its meaning: the final transcript, empty before finish.

### Input level

`crates/scriber-core/src/level.rs`, constants pinned by tests. The recorder adapter hands every sample block to the core's tap and computes nothing itself. The core takes the RMS of each 50 ms window of sound (`WINDOW_MS`, all channels' samples counted), converts it to dBFS and maps it linearly from -52 dBFS (`FLOOR_DBFS`, 0.0) to -6 dBFS (`CEILING_DBFS`, 1.0), clamped; silence and a non-number read 0. Decibels, not linear RMS, because speech would draw as a nearly flat line on a linear scale. The ceiling is deliberately near clipping: on a MacBook mic room silence is about -52 dBFS, dictation about -41 to -33 dBFS and the loudest about -27, but a close condenser mic drove quiet speech past the old -20 ceiling and pinned the bars to the top, and -6 dBFS RMS over 50 ms is near clipping, so only genuinely loud input reads 1.0. -52 dBFS (room silence) and below read 0.0, -41 dBFS about 0.24, -40 dBFS about 0.26, -33 dBFS about 0.41, -29 dBFS 0.5, -27 dBFS (the loudest measured) about 0.54, -20 dBFS about 0.70, and anything at or above -6 dBFS (a full-scale sine included) 1.0. One reading per window, and at most one per delivered block (the loudest window it completed), so the level event runs at no more than 20 a second. Each reading is sent outside the tap's lock. With the silence split on, the tap also finds the silences that close a segment (see Segments), and the feeder calls the split notifier once per block that closed one, also outside the lock.

### Filters

In `crates/scriber-core/src/transcript.rs`, all constants pinned by tests:

- **Silence.** A segment is silent when no 100 ms window (1,600 samples) reaches an RMS of 0.01 (-40 dBFS). A silent segment is never sent to the transcriber. Windowing keeps a few words in a long quiet segment from being averaged away.
- **Trailing silence.** Before a non-silent segment is transcribed, everything after the end of its last 100 ms window (a trailing partial window counts) whose RMS reaches the trim level, 0.002 (-54 dBFS), is cut, keeping 500 ms (8,000 samples) of padding after it, clamped to the segment's length. Leading silence is kept, and the saved segment audio (used by Retry and the library) is not trimmed; only what the transcriber hears is. Measured 2026-10-29: library entry 20261029-163217 (~32.8 s) ended in ~3 s of room tone near -58 dBFS with clicks peaking at an RMS of ~0.005, and large-v3-turbo appended "Thank you." to the real text; cutting at 29.8 s removed it in all three runs with every word kept. The trim level is separate from the 0.01 silence level on purpose, measured 2026-10-30: a Sennheiser XS LAV USB-C recording peaked at ~0.09 with a median window RMS of ~0.007, so at 0.01 the trim cut real speech ("a line under it. Let's make that change." from one segment, "every single recording." from another); a sweep of the 27 library recordings at 0.002 trimmed only true silence, up to 1.5 s, and on 20261029-163217 cut 0.7 s, ending at 31.8 s. That recording's phantom "Thank you." is now removed by the last-phrase rule (see Hallucinations), not by the trim, because its ~0.005 clicks survive a 0.002 trim. Relative-to-peak levels were measured as worse (up to 2 s of speech cut on a Jabra peaking at ~0.25).
- **Hallucinations.** Whisper invents text for silence and noise. A segment whose trimmed audio (see Trailing silence) is shorter than 10 s and whose whole text, trimmed and ignoring ASCII case, is one of "Thank you.", "Thank you", "Thank you very much.", "Thanks for watching!", "Thanks for watching.", "Thank you for watching.", "Thank you for watching!", "Bye.", "you", "[BLANK_AUDIO]", "(silence)" or "Subtitles by the Amara.org community" is treated as silent. The same words inside longer text, or in a segment whose trimmed audio is 10 s or more, are kept. Before that rule, the last phrase of the transcriber's reply is dropped when its whole text, trimmed and ignoring ASCII case, is on the list and no 100 ms window of its own span (from Whisper's segment timestamps) reaches 0.01. The test uses the silence level, not the trim level, so a quietly spoken final "Thank you." with no window at 0.01 is dropped by design, while one spoken at normal level is kept. At most one phrase is dropped, and never one but the last. A span past the end of the audio, or inverted, counts as silent. The short-segment rule above still applies afterwards to the remaining text. A phantom that Whisper merges into the previous phrase's text, or whose span starts before the end of the last loud window, is kept.
- **No letters or digits.** Text is trimmed; empty text, and text with no letter or digit (no char for which `char::is_alphanumeric` is true), is treated as silent at any segment length. Measured 2026-10-25: a 1.5 s noise thump above the silence level transcribed as "you" without a prompt and as "." with the style prompt.

### Glossary

The glossary file named by `vocabulary` in `settings.json` (an absolute path), else `vocabulary.txt` in the data folder, read from that path at each New and Discard (and at launch for a recovered session). One term per line; surrounding whitespace is trimmed; blank lines and lines whose first non-blank character is `#` are ignored; control characters are removed from terms. The prompt is the style sentence `Okay, here's what I need. First, check the board; then, once it's done, let me know.` followed, when there are terms, by one space and `Glossary: term1, term2, ...` with a period after the last term, built in file order while the whole prompt stays within 500 characters; the first term that would overflow ends the list. The style sentence uses part of that budget, leaving 404 characters for the terms, separators and trailing period after `Glossary: `, and terms past it are dropped in file order. No terms, a missing file, an unreadable file or one that is not UTF-8 gives the style sentence alone. The terms learned from the user's corrections (`learned_vocabulary` in `settings.json`, else `learned.txt` in the data folder, see Learning) come first, before the file's terms, within the same 500-character budget, and a file term equal to a learned one ignoring case is left out (`vocabulary::glossary`, then `vocabulary::prompt_for`); the cleanup pass gets the same list, cut to its 200 terms. Measured 2026-10-25 on a 44 s segment with ggml-large-v3-turbo: without a prompt long run-on stretches lost periods and commas, the style sentence plus a glossary restored them, and the style sentence alone produced "gonna". With a glossary-only prompt the smoke check turned "Talus" into "talos" and "Agent GTD" into "agent-gtd".

### Delivery

On `finished` the core writes the transcript to the clipboard and the notice says "Copied to the clipboard." If the clipboard cannot be written the transcript is still shown and the notice says "Could not copy to the clipboard: <reason>. Use Copy to try again." If every segment was silent the transcript is empty, nothing is copied, and the notice says "No speech was heard. If you spoke, check that Scriber may use the microphone in System Settings, Privacy & Security, Microphone." (macOS delivers silence, not an error, when the permission is denied.) The clipboard gets the transcript after the shortcut glyphs (see Shortcuts). Copy sends the text as edited in the box, unconverted; the core copies it and keeps it as the transcript.

`snapshot.rawText` is, on a finished session, Whisper's joined transcript before cleanup, the shortcut glyphs and the learned spellings; it is set even when it equals `text`, and is null in every other phase. It does not depend on the library: when the library writes `transcript.raw.txt` it is the same text. A Copy that edits the transcript does not change it. It is null after a relaunch, which means unknown; `transcript.raw.txt` in the library entry is the durable record.

### Cleanup

`crates/scriber-core/src/cleanup.rs` and `dictation.rs`, all constants pinned by tests. Optional, off by default (`settings.json` `cleanup`). When the last segment is heard and the joined transcript is non-empty, the cleanup setting is on and the ports have a `Cleaner`, the session stays `transcribing` (with `pending` 0 and no text) and one cleanup job is queued with the transcript and the glossary's terms, read from the glossary at that moment (so an edit made while recording applies to the cleanup but not to Whisper's prompt). The terms are cleaned like the prompt's (`vocabulary::terms`) and truncated once, to the first 200 (`MAX_TERMS`). The job POSTs, through the `Cleaner` port, to the same Ollama server as summaries, asking the model `settings.json` names in `cleanup_model` (`""` = `EngineConfig::summary_model`), read when the job runs, not when it is queued; a job that runs while a settings save is in progress may use the model saved before it (the save renames a complete file into place, so a job never reads half a file; an unreadable file would mean the default model). The system prompt is `PROMPT`:

> You correct a dictated transcript. Make only four kinds of change. First, where a word or phrase was misheard and sounds closely like one of the glossary terms (and fits the sentence), replace it with that term spelled exactly as in the glossary; never replace an unrelated name or foreign word just because it starts with a similar sound. Second, where the speaker explicitly spells out a word or name inside the transcript (for example, "X is spelled A-B-C"), use that spelling in normal title case (not all-caps unless it is an acronym) everywhere that word or name appears in the transcript (fixing any phonetic mishearing, including when joined to another word), while keeping the speaker's spelling sentence intact unless they were correcting a false start. Third, where the speaker corrected themselves while speaking (a false start, a repeated phrase, or words such as "I mean" or "what I actually meant was"), work out what they were trying to say. If their final restatement says it cleanly, keep that restatement exactly as spoken. If it does not, write what they were trying to say in words that match the rest of the transcript, its vocabulary and its tone, adding as few words they did not say as you can. Either way, delete the abandoned words. Fourth, where a clock time followed by a.m. or p.m. has a dot between the hour and the minutes, change the dot to a colon: 9.43 a.m. becomes 9:43 a.m. Leave every other number unchanged, including version numbers and decimals. Change nothing else: keep every other word, the word order, the spelling, the punctuation and the paragraph breaks exactly as they are. Do not rephrase, summarize, add, explain or answer anything else in the transcript. Record every change you make (or any spelled-out word, with `from` and `to` equal when already spelled right) in `replacements`, every new word or proper name the speaker spelled out in `learned` in normal title case, and the corrected transcript in `transcript` (unchanged when nothing needs changing).

and the user message `Glossary:\n<term per line>\n\nTranscript:\n<text>`, or `Glossary: none\n\nTranscript:\n<text>` with no terms. The reply is a `Reply { replacements: Vec<Replacement { from, to }>, learned: Vec<String>, transcript }`, with `Reply::new` giving an empty `replacements` and `learned`. `spelled(raw)` finds the words the speaker spelled out: each whitespace-separated token trimmed of leading and trailing non-alphanumerics and split on `-`, kept when it has at least three parts that are each one ASCII letter, as the lowercase concatenation of the letters, de-duplicated in first-found order. `filter(raw, reply)` judges only a short substitution (1 to 3 tokens a side, no ASCII digit on either side) and reverts every bogus one in the transcript (`transcript.replacen(to, from, 1)`, in replacement order) and drops it: with `fk` and `tk` the joined lowercase tokens of `from` and `to`, a replacement whose keys match is bogus when `spelled(raw)` holds `fk`, `to` has at least 4 ASCII letters and is all uppercase, and `from` has a lowercase letter; one whose keys differ is bogus when `spelled(raw)` holds `fk` or, with no spelled word a substring of `tk`, its Levenshtein distance × 5 exceeds the longer key's length × 2. `learned_terms(raw, reply, terms)` takes `learned` then each replacement's `to`, normalizes each to 1 to 3 words with at least 4 alphanumeric chars and only alphanumerics or `-` in a word, titles all-caps spellings and expands a `labs` compound into `Name` and `Name Labs`, and keeps a candidate not already in `terms`, grounded in the transcript or `raw`, and either containing a spelled word or a learned word the reply replaced with a term `learn::learn` accepts; it de-duplicates case-insensitively and returns nothing when more than `learn::MAX_RUNS` (5) qualify. `accept_reply(raw, reply, terms)` filters the reply, adds `spelled(raw)` (and the words of any learned entry grounded in a spelling) to the glossary, and then checks the filtered transcript with `accept`. The filtered transcript's tokens are its whitespace-separated pieces, trimmed of leading and trailing non-alphanumeric characters, lowercased, empty ones dropped; with `text` the reply trimmed of leading and trailing whitespace and of any trailing `"`, `\u{201d}` or `}` that `raw` does not end with, R the transcript's tokens, Y the reply's and G the tokens of every term, the first rule that matches rejects it: (1) `text` is empty (`rejected-empty`); (2) it contains three backticks (`rejected-fenced`); (3) R or Y is empty (`rejected-no-words`); (4) R has at least 20 tokens (`MIN_WORDS_FOR_RATIO`) and 3 × |Y| < |R| (`rejected-too-short`); (5) the tokens of Y not in G, less the longest common subsequence of them and R, number more than max(3, ⌊|R| / 20⌋) (`NEW_WORDS_MIN`, `NEW_WORDS_PER`), so a reply may add a few words of its own to repair a self-correction or write a clock time with a colon (each time rewritten from 9.43 to 9:43 counts as one new token), more for a longer transcript (`rejected-new-words`); (6) the last three tokens of R and of Y (fewer when there are fewer) share none (`rejected-cut-off`). Otherwise `text` is the transcript. The session then finishes as usual (saved, copied, archived) with the cleaned text when accepted and with the raw Whisper text otherwise: it fails closed on any error (the model unreachable, an error status, the timeout, a reply cut off at its length, a reply with nothing after its last `</think>`, a reply that is not JSON or has no string `transcript` field, a queue that refuses the job) and on any rejection, silently, with no error and no extra notice. With the library on, the entry's `cleanup` key records the outcome: `off` (no cleanup ran), `cleaned` (accepted and different, with Whisper's text in `transcript.raw.txt`), `unchanged` (accepted and identical), one of the six `rejected-*` labels (with the reply in `cleanup.reply.txt`), or `failed` (with the reason in `cleanup_error`). The summary and every stored copy of the transcript are written from the final transcript, which is the cleaned text when it was accepted, after the shortcut glyphs (see Shortcuts). With the library off nothing records the outcome. A cleanup outcome for another session, or one that arrives when the session is not waiting for it, is ignored.

**Keeping the model loaded.** While cleanup is on, the engine keeps the resolved cleanup model (`cleanup_model`, or `EngineConfig::summary_model` when empty) loaded in Ollama, so the first cleanup after a pause does not pay the cold-load cost: on its own `scriber-warm` thread (`crates/scriber-engine/src/warm.rs`) it warms the model at open and again every `keep_warm_every` (240 s, `KEEP_WARM_INTERVAL`) with `keep_alive` 10m (`KEEP_ALIVE`), never forever. Turning cleanup off or changing the model releases the old one (`keep_alive` 0), and the new one is warmed if cleanup is still on. Quitting releases it best effort on the quitting thread and may wait up to `RELEASE_TIMEOUT` (2 s) when Ollama is unresponsive, but never waits for a load in flight; a load still in flight at quit, or a crash or force-quit, leaves the model loaded at most 10 minutes. Failures (Ollama down, the model not installed) are silent, retried each tick and never affect dictation; there is no UI for it. The summary model is not warmed separately (it is kept loaded only when it is the same model). The kept-warm model follows the settings as of open and each save through the app (`Engine::set_settings`), so a `settings.json` edited by hand takes effect at the next launch. To check it on the Mac: `ollama ps` lists the cleanup model with UNTIL about 10 minutes from now while cleanup is on; it is gone within 2 s of quitting, after cleanup is turned off, or after a model change (only the new one is listed); and Ollama's server log records each `POST /api/generate` with its status.

### Shortcuts

`crates/scriber-core/src/shortcuts.rs`: `to_glyphs`, a pure function with no setting. Dictated keyboard shortcuts come out as Mac glyphs, by a deterministic rule that runs last, in `Dictation::finish`, after cleanup, on every path (cleanup off, unchanged, cleaned, rejected, failed, a refused queue, retry), and not on Copy. `transcript.raw.txt` stays as spoken. The cleanup prompt and `accept` are untouched by the shortcut rule and the cleanup request carries Whisper's unconverted text. With the library off the conversion leaves no record beyond the transcript itself.

A match is modifiers, a separator and a key. Modifier words: command or cmd ⌘, control or ctrl ⌃, option or alt ⌥, shift ⇧, written in the order ⌃⌥⇧⌘ whatever order was spoken, duplicates collapsed. Separators: a space, a hyphen, `+` (with any whitespace around it) or the word plus (`-plus-`, ` plus `). Keys: comma `,` period or dot `.` slash or forward slash `/` backslash `\` equals or equal `=` minus, dash or hyphen `-` semicolon `;` backtick `` ` `` quote `'` left or open bracket `[` right or close bracket `]` return or enter ↩ tab ⇥ escape or esc ⎋ delete or backspace ⌫ up ↑ down ↓ left ← right →; space stays the word Space; a single letter is capitalised; a digit and F0 to F19 are kept. Two-word keys may be joined by a hyphen. Everything matches case-insensitively. The match must not touch a letter, digit, `_` or `-` on either side. The first complete match, trying the longest modifier chain first, wins, and scanning resumes after it.

It converts only with strong evidence: ⌘ or ⌃ among the modifiers, two or more distinct modifiers, a hyphen in the match, or enter, return or tab as the key. A single letter key also needs ⌘, ⌃ or a hyphen. So Option 1, shift left and Option B stay as words, and Option-click stays because click is not a key. A few misfires are accepted and pinned by tests (Shift Enter as a phrase, Control A and Control B).

### Learning

`crates/scriber-core/src/learn.rs`, pure functions any app can use: `candidates`, `learn`, `remember` and `enforce`. The triggers are Copy and Accept on a finished session (Copy after the clipboard write succeeds) and an accepted cleanup: the core compares the transcript the user was shown (after cleanup, the shortcut glyphs and the learned spellings) with the edited text Copy sends, and a cleanup learns its `learned_terms` through the same `learn::remember`/`store::save_learned`/undo path, logging the same `learn` line with `found` the kept learned-term list; `cleanup.reply.txt` holds the rejected reply's `transcript` field only. Nothing is learned from a selection copied with ⌘C, from a library copy, or from edits made after Copy outside Scriber. There is no dictionary lookup and no setting.

Each text is split on whitespace; each piece is stripped of leading and trailing characters that are not letters or digits, then of a trailing `'s` or `’s` when more is left; empty pieces are dropped. A word starts a sentence when it is the text's first, or when the previous piece, less any trailing `"` `'` `”` `’` `)` `]`, ends with `.`, `!` or `?`. Equal leading and trailing words are matched, the middle is aligned by a longest common subsequence of words (exact, case-sensitive), and each stretch of unmatched words between matches is a run. A run with no words on one side (an insertion or deletion) or more than 3 (`MAX_RUN_WORDS`) on either side is ignored. A run qualifies, as its edited words joined by single spaces, when it is (a) case-only: the same word count, each pair equal ignoring case, and some pair differing other than in the first letter of a word that starts a sentence (or differing in length); a case-only run is decided by this rule alone; (b) a join or split: both sides equal once lowercased with spaces and hyphens removed (`tight beam` to `tightbeam`, `g t d` to `GTD`); or (c) a close spelling fix: one word each side, the new word at least 4 characters (`MIN_FIX_CHARS`), and the Levenshtein distance of the lowercased words at most a third of the longer one's length (rounded down), at least 1. Anything else is a style edit. When more than 5 runs qualify (`MAX_RUNS`) the Copy was a rewrite and nothing is learned; otherwise the terms are learned once each, compared ignoring case. All counts are over characters, never bytes.

The learned list lives at `store::learned_path`: `learned_vocabulary` in `settings.json` when it names an absolute path, else `learned.txt` in the data folder; it is independent of `vocabulary`, and the app never writes the glossary file. One term per line, newest first: learned terms go to the top in the order found, an older line equal to one ignoring case is removed (so a new casing replaces the old), the list keeps 100 terms (`MAX_LEARNED`), and a term spelled exactly as in the glossary file is not added. It is written atomically (`<learned path>.partial`, then renamed). An unreadable learned list is treated as empty and can be overwritten; one that is not UTF-8 stops learning (the log says `unreadable`) and enforcement until it is fixed.

Learned terms come first in the Whisper prompt and the cleanup glossary (see Glossary). After the shortcut glyphs, `Dictation::finish` rewrites every whole-word match of a learned term to its learned spelling: case-insensitively, at sentence starts too, where up to three words written with one space or hyphen between them count as the joined term (`tight beam` and `Tight-Beam` become `tightbeam`), and never inside a longer word or next to `_` or `-`. A term with anything but letters, digits, spaces and hyphens is not enforced. Terms in the glossary file are never enforced, because many are ordinary words. With the library on, `transcript.raw.txt` keeps what Whisper heard when enforcement changed the text.

`snapshot.learned` is `[]` except in `finished` after a learning Copy or Accept, when it holds the terms that Copy added; a later Copy that learns nothing leaves it as it was. New, Discard and a relaunch clear it (it lives in memory only). Undo (`undoLearn`, legal only in `finished`) writes the learned list back as it was before the last learning Copy (0 bytes when there was none), restoring a line a new casing replaced, and clears `learned`; with nothing to undo it changes nothing but the revision. A failed write is refused with "Could not undo learning: <reason>" and changes nothing. The notice stays "Copied to the clipboard.". Accept is the engine-level action for apps that insert the text themselves: it learns from the edited text exactly as Copy does, writes nothing to the clipboard, sets no notice, and Undo (`undoLearn`) undoes it the same way; the Scriber window offers no Accept button.

### Failure and crash safety

Failures are a visible state, never a silent empty transcript. A segment whose transcription fails, or that the queue refuses, makes the session `failed` once nothing is pending, with `error` naming the first failed part: "Part 2 of 3 could not be transcribed: <reason>. Retry to try again." Retry reads that part's WAV back; if it cannot be read the part fails again with "its audio could not be read: <reason>".

The session's WAV files stay on disk until the next New or Discard, and a finished session's transcript is kept beside them (`segments/transcript.txt`, rewritten by each Copy; a failure to write it only means a relaunch offers Retry instead). With the library on, a finished session with a non-empty transcript moves its audio into `library/<id>/` (see The library) and keeps only `segments/transcript.txt` and `segments/started.txt`, so a relaunch shows it as finished with no parts. At launch the core reads that folder: with a transcript the session starts `finished`, showing it (nothing is copied again); with segments but no transcript (a crash, or a quit while transcribing) it starts `failed` with "The last session was not transcribed. Retry to transcribe its N recorded parts, or start a new session." Quitting shuts the engine down (`Engine::shutdown`), which saves the open segment's audio, lets a transcription already decoding finish and releases the cleanup model kept warm in Ollama (best effort, at worst 2 s when Ollama does not answer); if its result is saved before the process exits the next launch shows it, otherwise it offers Retry with the audio intact. A quit or crash during cleanup leaves the session not transcribed (its transcript is saved only on finishing), so the next launch offers Retry, which transcribes and cleans it up again; shutdown does not wait for a cleanup job. The transcript is written atomically (to `segments/transcript.txt.partial`, then renamed), so a relaunch never sees a truncated one.

Record and Resume open the input device saved in `input_device` (`""` is the Mac default). When a named device will not open, the core tries the Mac default once and, when that opens, records from it with the notice "<wanted> is not available, so this part is recording from the Mac default, <opened>." (`dictation::input_fallback`; shown in the status line while recording), leaving the saved choice as it is. A microphone that will not start refuses Record or Resume ("Could not start recording: <reason>", the Mac default's reason after a fallback) only when the Mac default fails too, and leaves the session where it was. A microphone that fails while recording loses only that segment: Pause still pauses, and the notice says "The microphone stopped: <reason>. The last part was not recorded." A segment whose WAV cannot be saved still transcribes from memory, with the notice "Could not keep this part's audio for Retry: <reason>."

## The library

`crates/scriber-core/src/library.rs`, with the archive run from `dictation.rs`. Off by default in the engine (`EngineConfig::library`), so an app embedding it keeps no audio it did not ask for; the desktop app turns it on. With it off the core writes nothing under `library/`, writes no `segments/started.txt`, queues no encode or summary and leaves `libraryRevision` at 0.

**Session start.** The session's first Record (from `ready`) reads the clock and keeps the title `YYYY-MM-DD HH:MM:SS` (24-hour, local time) in memory and in `segments/started.txt` (a write failure is ignored). New and Discard forget it. At launch, `started.txt` is used when its trimmed contents are exactly 19 characters shaped `DDDD-DD-DD DD:DD:DD`; otherwise the entry is titled by the clock when it is archived. So a crashed session finished later by Retry keeps the time it was recorded.

**Archive.** When a session becomes `finished` with a non-empty transcript (after the transcript is saved and copied), synchronously under the session lock, all through the `Files` port: (1) the id is the title without `-` and `:` and with the space as `-` (`20261026-140309`); when a folder in `library/` already has that name, `-2`, `-3` and so on are tried. (2) Every stored segment is read in order, unreadable ones skipped, and their samples are joined into `library/<id>/audio.wav` (not written when none was read). (3) `transcript.txt` is written, then `transcript.raw.txt` when an accepted cleanup or the shortcut glyphs changed the text, then `cleanup.reply.txt` when a cleanup reply was rejected; a failed write fails the archive. (3a) With `keep_segments` on in `settings.json` (read once, at this finish), each stored segment's bytes are copied unchanged, never decoded or re-encoded, to `library/<id>/segments/segment-NNNN.wav` (same names, kept whether or not they decode), after (3) and before (4); every segment is attempted, and a failed read or write never fails the archive: the first error appends ` Could not keep the exact audio of the parts: <error>.` to the notice (after one space), and Encode (`audio.wav` only) and the listing ignore the extra folder. (4) `entry.json` is written to `entry.json.partial` and renamed into place, last, so an entry without one never lists: `{"id","title","summary","summary_source","cleanup",["cleanup_error",]"duration_ms"}` in that order, compact, with the excerpt as the summary, `summary_source` `"excerpt"`, `cleanup` the cleanup outcome (see Cleanup) and `cleanup_error` only when the cleanup failed. (5) Only when 1 to 4 succeeded are the segment WAVs removed (a failure to remove one is ignored). (6) `libraryRevision` and `revision` are bumped. (7) An encode job is queued when `audio.wav` was written, and a summary job when `settings.json` has summaries on. If step 1, 2, 3 or 4 fails (not 3a), every segment WAV stays, no `entry.json` exists, nothing is bumped and the session is exactly as finished left it. A session that heard nothing, a failed one and a discarded one are never archived; Retry that later finishes is archived then. `libraryRevision` starts at 0 at launch and is never reset by New or Discard. `duration_ms` and `summary_source` are written but nothing reads them yet.

**Encode.** Off the transcription path, on a job thread: `audio.wav` is encoded to `audio.m4a` (measured 2026-10-26: a 43.9 s segment went from 1,403,948 bytes of WAV to 186,402 of 32 kbit/s AAC, and decoded back to 43.872 s). On success `audio.wav` is removed; on failure (afconvert missing, as on every non-macOS host, or failing) any `audio.m4a` is removed and `audio.wav` kept: audio is never lost.

**Excerpt.** Every whitespace run (`char::is_whitespace`, newlines included) becomes one space and the ends are trimmed. Text of 30 characters or fewer is the excerpt whole. Otherwise the first 30 characters are taken, cut at the last space among them when that space is at character index 20 or later, trailing whitespace and `,;:-.` are trimmed, and `...` is appended. Examples (each pinned in the core and the mock): "This is part 1 of the dictation." gives "This is part 1 of the..."; "Okay, here's what I need. First, check the board; ..." gives "Okay, here's what I need..."; "Supercalifragilisticexpialidocious is long" gives "Supercalifragilisticexpialidoc..."; "Abcdefghijklmnopqrstuvwxyzabc, more" gives "Abcdefghijklmnopqrstuvwxyzabc..."; 19 `a`, a space and 20 `b` keeps 10 `b` (the space at index 19 is too early to cut at); 20 `a`, a space and 20 `b` gives 20 `a` and `...`. Characters are counted, not bytes.

**Summary.** Off the transcription path, on a job thread of its own, so a slow or hung Ollama never delays transcribing or archiving the next session. The model is `settings.json`'s `summary_model` (`""` = `EngineConfig::summary_model`), read when the job runs, not when it is queued; a job that runs while a settings save is in progress may use the model saved before it (the save renames a complete file into place, so a job never reads half a file; an unreadable file would mean the default model). The engine POSTs to `<ollama_url>/api/chat` (default `http://127.0.0.1:11434`, model `qwen3.8:27b-mlx`) `{"model": <the model>, "stream": false, "think": false, "messages": [{"role": "system", "content": "You write a one-sentence summary of a dictated note, at most 15 words, plain text, no quotes, no preamble."}, {"role": "user", "content": <transcript>}]}` with a 60 s overall timeout; `think: false` keeps qwen from spending ~300 tokens thinking (measured 2026-10-26 with ollama 0.40.6: about 2 s cold, 0.5 s warm). The engine first cuts a reply containing `</think>` to the trimmed text after its last `</think>`. The core collapses the reply's `message.content` to one line, strips one pair of surrounding straight or curly double quotes, and writes it into `entry.json` as `summary` with `summary_source` `"ollama"` and `summary_model` the model name sent (`""` = the engine's default) (through `entry.json.partial` and a rename, every other key kept), then bumps `libraryRevision` and `revision`. Any failure keeps the excerpt silently: connection refused, a non-2xx status, the timeout, invalid JSON, no `message.content`, nothing after `</think>`, or content empty after cleaning. A summary that lands after New or Discard still updates its entry: it is keyed by id, not by session. Failed summaries are not retried, and turning summaries back on does not summarize older entries.

**Settings.** `settings.json` in the data folder, `{"summaries": bool, "library_open": bool, "vocabulary": string, "cleanup": bool, "summary_model": string, "cleanup_model": string, "library_width": number, "input_device": string, "silence_split_ms": number, "keep_segments": bool, "learned_vocabulary": string, "model_folder": string, "toggle_shortcut": string}` in that key order, compact; `summaries` and `library_open` true by default, `cleanup` false (a missing key or one that is not a bool means false). A missing, unreadable or invalid file means the defaults; each key is read on its own (a missing key or one of another type takes its default; unknown keys are ignored). `vocabulary` is the glossary file's absolute path; empty, missing, not a string or relative (not starting with `/`) means the default, `vocabulary.txt` in the data folder, stored as `""`. The engine answers the default as its absolute path, so over the bridge `vocabulary` is never empty. On write every field is replaced (`cleanup` included, like `summaries`), except that an empty `vocabulary` keeps the saved path (a client that has not read the settings sends `''`), and the absolute default path is stored as `""`; a rejected stored value (a relative path, say) is discarded on the next save. `learned_vocabulary` is the learned list's absolute path under the same read rule: empty, missing, not a string or relative means the default, `learned.txt` in the data folder, stored as `""`; the engine answers that default as its absolute path, and on write an empty value keeps the saved path while the default's absolute path is stored as `""`. `model_folder` is the model's absolute folder under that same read rule: empty, missing, not a string or relative means the default, `models` in the data folder, stored as `""`; the engine answers that default as its absolute path, and on write an empty value keeps the saved folder, `<data folder>/models` is stored as `""`, a relative path is stored verbatim and dropped on read, and each write is logged to `model-log.jsonl`. `summary_model` and `cleanup_model` name the Ollama model for summaries and for cleanup; `""` (the default, and what a missing key or a non-string value means) is `EngineConfig::summary_model`, the same default for both. A string is kept exactly as stored. The engine answers the default by name, so over the bridge neither is empty; on write each on its own: `''` keeps the saved model and the default's name is stored as `''`. Saving writes `settings.json.partial` and renames it into place. Turning summaries off affects new entries only. `library_open` is the drawer's state, which the window keeps there. `library_width` is the drawer's width in px (a number, default 220): read as a non-negative integer clamped to 110 to 440, and anything else (missing, negative, a fraction, another type) means 220; it is written after `cleanup_model`. `input_device` is the input device to record from, by name (default `""`, the Mac default): a string is kept exactly as stored, anything else means `""`; it is written after `library_width`, and the engine stores and answers it verbatim, `""` included (it never keeps the saved one for `""`, unlike the models, and never resolves it to a device name). `silence_split_ms` is the silence split in ms (default 0, off): a non-negative integer kept when it is 0 or in 1000..=10000 (`SILENCE_SPLIT_MIN_MS`, `SILENCE_SPLIT_MAX_MS`), and anything else (out of range, negative, a fraction, another type, missing) means 0; it is written after `input_device`. `keep_segments` (default false) is true only for the JSON boolean true (a missing key or another type means false); it is hidden (no Settings UI), edited in `settings.json` by hand, read at each finish, and written after `silence_split_ms`, before `learned_vocabulary`. `settings.json` owns it: `Engine::set_settings` ignores the sent value and keeps the saved one, so a settings change made in the app never changes it. `toggle_shortcut` is the global shortcut in Scriber's canonical form (`Opt+Cmd+D`); it is kept only when `crate::menubar::accelerator` accepts it, and anything else (missing, not a string, not Scriber's form, or no ⌥/⌘) means `Opt+Cmd+D`; a saved value is stored verbatim, so the read rule is the only filter, and it is written last.

**Ids.** An id is 8 digits, `-`, 6 digits, optionally `-` and more digits. Every core and engine function that takes an id treats any other string as not in the library, which keeps an id from reaching outside `library/`. The list takes the folders in `library/` whose names are ids and whose `entry.json` parses with a string `title` and `summary` (extra keys are ignored; the id is always the folder's name), newest first: by the 15-character base id, then by suffix (none counts as 1).

## Engine API

`crates/scriber-engine` is the whole capability as a library: another Rust app depends on it (as a git dependency) and the desktop app is one client of it. It has no Tauri and no async runtime; jobs run on std threads.

- **`EngineConfig`**: `data_dir` (the consumer's data folder, laid out as in The data folder; it need not exist), `model: ModelSource`, `clipboard: Option<Arc<dyn Clipboard + Send + Sync>>`, `library: bool` (keep finished sessions in the recording library; default false), `ollama_url: String` (default `DEFAULT_OLLAMA_URL`, `http://127.0.0.1:11434`) and `summary_model: String` (default `DEFAULT_SUMMARY_MODEL`, `qwen3.8:27b-mlx`; the same server does the cleanup, and this model is the default for both summaries and cleanup when `settings.json` names none) and `editor: PathBuf` (the program that opens the glossary in a text editor with `-t <path>`; default `OPEN`, macOS's `/usr/bin/open`) and `keep_warm_every: Duration` (how often the cleanup model's keep-alive is renewed; default `KEEP_WARM_INTERVAL`, 240 s). `EngineConfig::new(data_dir)` takes the default model, no clipboard, no library, `/usr/bin/open` and `KEEP_WARM_INTERVAL`.
- **`ModelSource`**: `Local(path)` uses a ggml model file where it is and never downloads; a missing file says "The speech model is missing from <path>." and `download_model()` is refused with `DictationError::LocalModel`. `Download(Source { url, bytes, sha256 })` downloads into `settings.json`'s `model_folder` (the data folder's `models/ggml-large-v3-turbo.bin` when unset) when missing and verifies size and SHA-256, so a mirror only needs its own URL. The default is `Download(Source::default())`: Hugging Face `large-v3-turbo`, pinned above.
- **Opening**: `Engine::open(config, events)` with the real adapters (`CpalRecorder`, `Whisper`, `HttpDownloader`, `LocalClock`, `Afconvert` at `/usr/bin/afconvert` over the data folder, and `Ollama` at `ollama_url` with `summary_model` twice: the summarizer with a 60 s timeout, the cleaner with `CLEANUP_TIMEOUT`, 120 s, and the warmer with `WARM_TIMEOUT`, 60 s), or `Engine::with_adapters(config, make, events)` with others (`make` gets the level sink to hand to its recorder and returns `Adapters { recorder, transcriber, downloader, clock, encoder, summarizer, cleaner, warmer }`; `warmer` is an `Arc<dyn Warmer + Send + Sync>`, shared with the keep-warm thread). Either recovers the data folder as the app does at launch and starts the warm-up, or the download, on a job thread. The session is assigned under its lock before any job it queued can record an outcome.
- **`Event`**: `Level(f64)` (0 to 1, at most 20 a second while recording) and `State(Snapshot)` (whatever `dictation-changed` carries). A method that answers a snapshot also delivers it as `Event::State`, on the caller's thread with the session lock held, so the window's commands, the tray and the hotkey share one stream and none can go stale.
- **Threading**: `Event::State` is delivered on the caller's thread with the session lock held when a method answers a snapshot, and on a job (or `scriber-split`) thread with the lock held otherwise, so the callback must never call the engine (it deadlocks); forward it to a channel. `Event::Level` is delivered on the audio thread and must return quickly. A segment closed at a silence is taken into the session on a short-lived `scriber-split` thread, which locks the session and delivers `Event::State` with the lock held, as job threads do: the recorder's split notifier runs on the audio thread and only spawns that thread, because Pause holds the session lock while `stop` drops the stream, which waits for the audio callback, so locking from the callback could deadlock. A failed spawn loses nothing: the closed segment waits in the capture and the next stop hands it over. `Engine` is `Send + Sync` and `Clone`; dropping the last handle while no job runs drops the adapters.
- **Recording**: `record()`, `pause()`, `resume()`, `stop()` (Done), `discard()`, `retry()`, `download_model()`, and `act(action, text)` for any action. Record then stop, with no pause, is the primary path. `record()` from idle or finished starts a new session first (deleting the last one); it never applies New from failed, which would delete audio not yet transcribed: it refuses ("Cannot record while failed."), and the consumer retries or discards.
- **The tray and the hotkey**: `toggle()` is the menu bar's one gesture: it takes the session lock once, reads the phase and sends what `scriber_core::menubar::toggle` decides -- `record()` from idle, ready or finished (which applies New first from the last two), Done while recording, Resume while paused, nothing while transcribing or failed -- writes one `menubar-log.jsonl` line and answers the snapshot. After `shutdown()` every press answers `ShutDown`, in every phase. `toggle_accelerator()` answers the saved shortcut in the global-hotkey plugin's form (`Alt+Super+KeyD` for `Opt+Cmd+D`), never `None` because `settings::load` already filtered the value; it takes the session lock, so it is never called from the events callback. `log_menubar(&Log)` writes one line through `store::log_menubar`, best effort, and takes no lock.
- **Waiting**: `wait(timeout)` answers a finished session's text at once, a failed session's error as `EngineError::Failed`, `NotStopped` while idle, ready, recording or paused, and while transcribing waits on a condition variable paired with the session lock, until the deadline (`Timeout`). `stop_and_wait(timeout)` is `stop()` then `wait`. With cleanup on, the wait includes the cleanup call, up to `CLEANUP_TIMEOUT`, so a consumer should allow for it (the crate example waits 300 s). `wait` answers the final transcript, glyphs included. A finished session recovered at open answers its old text until `record()` starts a new one.
- **Shutdown**: `shutdown()` takes the session lock, refuses new work from then on (no job starts, so a download that finishes later queues no warm-up), pauses a recording so its audio is saved, releases the lock and then frees the speech model (`Transcriber::unload`). It blocks for at most the one model load or transcription already running, which finishes first; calls still waiting for the model are refused. It is idempotent on every clone and thread, and each call returns only once the model is freed. On the first call it then releases the cleanup model kept warm in Ollama (see Keeping the model loaded), best effort on the calling thread: the Ollama adapter waits at most `RELEASE_TIMEOUT`, 2 s, and a load in flight is never waited for. It answers a `ShutdownReport { first, paused_recording, freed_model }`. Afterwards `act` (and every action method), `record`, `wait` and `stop_and_wait` return `EngineError::ShutDown` ("The engine has shut down.") and leave the session unchanged; `state()` still answers; a waiter already blocked keeps waiting for the transcription in flight or its timeout. On macOS a consumer MUST call it before the process exits: whisper.cpp's Metal device is a C++ static freed at exit that aborts (`GGML_ASSERT([rsets->data count] == 0)`) while a whisper context is alive, and dropping every `Engine` handle is not enough, because a job thread may still hold the engine. The desktop app calls it on `RunEvent::Exit`, which Cmd-Q, the menu Quit and closing the last window all reach before AppKit's `exit()`. `scripts/exit-check.sh` checks it on the Mac.
- **Library**: `library()` lists the entries newest first (`LibraryEntry { id, title, summary }`), and is empty without touching the data folder when the library is off; it does not wait for the session lock. `library_transcript(id)` answers an entry's transcript, and `library_copy(id)` puts it on the configured clipboard; both answer `EngineError::NotInLibrary` ("That recording is no longer in the library.") for an id that is not an entry's, a missing transcript or the library off, and `library_copy` answers `EngineError::Refused(DictationError::Clipboard(..))` when the clipboard fails. Library changes arrive as `Event::State` snapshots whose `library_revision` grew.
- **Settings**: `settings()` reads `settings.json` (the defaults where there is none), with an empty `vocabulary` answered as `<data_dir>/vocabulary.txt`, an empty `learned_vocabulary` as `<data_dir>/learned.txt`, an empty `model_folder` as `<data_dir>/models`, and an empty `summary_model` or `cleanup_model` as `EngineConfig::summary_model`, and `input_device` stored and answered verbatim (`""` is the Mac default), and `set_settings(s)` saves it by the write rule in Settings above and answers with `settings()`, whether or not the library is on; a write failure is `EngineError::Settings` ("Could not save the settings: <reason>."). `open_vocabulary()` creates the glossary at `settings().vocabulary` empty when it is missing (its folder too; an existing file is never truncated, and a created one stays even when the editor fails), then runs `<editor> -t <path>`; `open_learned_vocabulary()` does the same for `settings().learned_vocabulary`; a failure is `EngineError::Editor` ("Could not open the vocabulary file: <reason>."). `ollama_models()` lists the models installed on the Ollama server through `installed_models(ollama_url)`: GET `<ollama_url>/api/tags` within `TAGS_TIMEOUT` (5 s), the `models[].name` strings sorted and de-duplicated (entries without a string name skipped), minus every entry whose name, lowercased, contains `embed` or whose `capabilities`, when it is an array, lacks `"completion"`; an unreachable server, an error status, the timeout, invalid JSON or a reply without a `models` list is `EngineError::Ollama` ("Local AI needs Ollama: <reason>."). It takes no session lock. After `shutdown()`, `set_settings` answers `ShutDown`; `settings()`, `input_devices()`, `ollama_models()`, `open_vocabulary()`, `open_learned_vocabulary()`, `library()`, `library_transcript()` and `library_copy()` keep working.
- **Microphones**: `input_devices()` answers the recorder's `inputs()`, `InputDevices { default_device, others }` (the system default's name and every other input device's, sorted case-insensitively), for choosing `Settings::input_device`. It takes no session lock and keeps working after `shutdown()`; a failure is `EngineError::Microphones` ("Could not list the microphones: <reason>."). `EngineConfig` has no microphone field: the choice lives in the settings, read at each Record and Resume.
- **Clipboard**: with `clipboard: None` the transcript is copied nowhere, and the snapshot's notice still says "Copied to the clipboard." (pinned by a test).
- **Breaking change (learned vocabulary)**: `Settings` gained `learned_vocabulary`, so Rust callers building a `Settings` literal must add it (other apps set it with `set_settings` and read it with `settings()`; there is no `EngineConfig` field).
- **Breaking change (model folder)**: `Settings` gained `model_folder`, so Rust callers building a `Settings` literal must add it (other apps set it with `set_settings` and read it with `settings()`; there is no `EngineConfig` field).
- **Breaking change (keep_segments)**: `Settings` gained `keep_segments`, so Rust callers building a `Settings` literal must add it.
- **Breaking change (silence split)**: `Settings` gained `silence_split_ms`, so Rust callers building a `Settings` literal must add it (other apps set it with `set_settings` and read it with `settings()`; there is no `EngineConfig` field), and a custom `Recorder` must implement `start(device, split_ms)`, `take_closed` and `on_split`.
- **Breaking change (toggle shortcut)**: `Settings` gained `toggle_shortcut`, so Rust callers building a `Settings` literal must add it (other apps set it with `set_settings` and read it with `settings()`; there is no `EngineConfig` field). `Engine` gained `toggle()`, `toggle_accelerator()` and `log_menubar()`, and `scriber-engine` re-exports `scriber_core::menubar`.
- **Not yet**: no streaming within a segment. Per-segment partial text is published in `Snapshot.partial` as each segment's transcription lands. `Snapshot` gained `partial` and `raw_text`, so Rust callers building a `Snapshot` literal must add them; `raw_text` is computed in core and needs no library. `Action::Accept` is the engine-level action for apps that insert the text themselves. `Event` is not `#[non_exhaustive]` today, but a streaming mode would add a variant (and a mode), not change these.

## Bridge contract

Tauri camel-cases argument names. `tests/e2e/contract.spec.ts` reads `src-tauri/src/lib.rs` and fails when a command, an argument or the event name disagrees with `bridge.ts`. `crates/scriber-core/tests/fixtures/bridge-shapes.json` holds an example of every JSON shape; the core's serde tests and the mock's honesty test both check against it.

### Commands

| Command | Arguments | Returns | Errors |
|---|---|---|---|
| `dictation_state` | none | `Snapshot` | never |
| `dictation_act` | `action: Action`, `text: string` | `Snapshot` after the action (`downloadModel` included) | the core's refusal, as one sentence (see above) |
| `library_list` | none | `LibraryEntry[]`, newest first | never |
| `library_get` | `id: string` | `string`, the entry's transcript | "That recording is no longer in the library." |
| `library_copy` | `id: string` | nothing; the transcript is on the clipboard | "That recording is no longer in the library."; "Could not copy to the clipboard: <reason>" |
| `settings_get` | none | `Settings` | never |
| `settings_set` | `settings: Settings` | `Settings`, as saved | "Could not save the settings: <reason>."; "The engine has shut down." |
| `vocabulary_open` | none | nothing | "Could not open the vocabulary file: <reason>." |
| `learned_vocabulary_open` | none | nothing | "Could not open the vocabulary file: <reason>." |
| `ollama_models` | none | `string[]`, the installed Ollama models' names that can generate text (embedding models hidden), sorted | "Local AI needs Ollama: <reason>." |
| `input_devices` | none | `InputDevices`: the Mac's default input device and every other one, by name | "Could not list the microphones: <reason>." |

`text` is the edited transcript for `copy` and `accept` and is ignored (the bridge sends `""`) for every other action. Errors arrive in the webview as a rejected promise carrying one readable sentence. The app's version comes from Tauri's own `getVersion()` (`@tauri-apps/api/app`), not a command of ours, and Browse… for the vocabulary file and the learned list is the dialog plugin's native open panel (`open` from `@tauri-apps/plugin-dialog`, one `.txt` file, starting at the current path; the capability grants `dialog:allow-open`), which answers a path or null; the panel is the same for both files, and Browse… and Open in Text Editor appear twice in Settings. Full-screen state comes from Tauri's own `isFullscreen()` and `onResized()` (`@tauri-apps/api/window`), not a command of ours, and needs no capability beyond `core:default`.

### Events

| Event | Payload | When |
|---|---|---|
| `dictation-changed` | `Snapshot` | the session changed: a command's action answered a snapshot (delivered on the caller's thread with the session lock held), or a job changed it -- a segment's transcription finished (or failed), whether or not the phase changed (a session archived into the library on finishing included); the model's download moved another whole percent, finished or failed; the warm-up finished (unchanged); an encode finished (unchanged); a summary was written (`libraryRevision` grew) or failed (unchanged); a part closed at a silence (on a `scriber-split` thread) |
| `dictation-level` | `number` (0 to 1) | while recording, one per 50 ms window of sound (at most 20 a second); see Input level |

Commands and events can arrive out of order (a segment can finish before the command that queued it has answered), so the window keeps the snapshot with the highest `revision`; it keeps one of equal revision too (`accept` compares `<`), so a command's snapshot arriving both as its answer and as `Event::State` changes nothing. There is no library event: the window lists the library again whenever an accepted snapshot's `libraryRevision` is higher than the one it last listed for.

### JSON shapes

```ts
type Phase = 'idle' | 'ready' | 'recording' | 'paused' | 'transcribing' | 'finished' | 'failed';
type Action = 'new' | 'record' | 'pause' | 'resume' | 'done' | 'discard' | 'retry' | 'copy' | 'accept' | 'downloadModel' | 'undoLearn';

interface Download {
  receivedBytes: number;
  totalBytes: number; // the model's size
}

interface Snapshot {
  revision: number; // grows with every applied action and every accepted result
  phase: Phase;
  recordedMs: number; // audio in the closed segments
  segments: number; // segments recorded in this session
  pending: number; // of those, still transcribing
  text: string; // the transcript once finished, else ""
  error: string | null; // why the session failed, when phase is "failed"
  notice: string | null; // one sentence about the last action
  modelError: string | null; // why the model is missing, unless it is downloading
  download: Download | null; // the model's download, while it runs
  libraryRevision: number; // grows when an entry is added or its summary replaced (each also grows revision)
  microphone: string | null; // the input device opened for the latest segment; null before the first Record
  learned: string[]; // the terms the last Copy learned, until Undo, New, Discard or relaunch; [] otherwise
  partial: string; // the heard segments' raw Whisper text so far, joined in recording order with a blank line; "" for a new session
  rawText: string | null; // finished only: Whisper's joined transcript before cleanup, glyphs and learned spellings; null before finish, and after a relaunch
}

interface LibraryEntry {
  id: string; // "20261026-140309", or "20261026-140309-2" after a collision
  title: string; // "2026-10-26 14:03:09", the session's start in local time
  summary: string; // the local model's sentence, or the excerpt
}

interface Settings {
  summaries: boolean; // summarize new entries with the local model
  libraryOpen: boolean; // the library drawer is open
  vocabulary: string; // the glossary file's absolute path; send '' when unknown (the saved one is kept)
  cleanup: boolean; // clean up each transcript with the local model
  summaryModel: string; // the Ollama model for summaries; send '' when unknown (the saved one is kept)
  cleanupModel: string; // the Ollama model for post-processing; send '' when unknown (the saved one is kept)
  libraryWidth: number; // the library drawer's width in px, a whole number, 110 to 440
  inputDevice: string; // the input device to record from, by name; '' is the Mac default (stored and answered verbatim)
  silenceSplitMs: number; // ms of silence that closes the running part while recording; 0 is off
  keepSegments: boolean; // hidden: no UI, set by editing settings.json; the app never changes it
  learnedVocabulary: string; // the learned list's absolute path; send '' when unknown (the saved one is kept)
  modelFolder: string; // the speech model's absolute folder; send '' when unknown (the saved one is kept), and the engine answers <data folder>/models
  toggleShortcut: string; // the global shortcut in Scriber's form (Opt+Cmd+D); the engine answers the default when the stored value cannot be used
}

interface InputDevices {
  defaultDevice: string | null; // the Mac's default input device, null when there is none
  others: string[]; // every other input device: no empty names, not the default, sorted case-insensitively (ties by byte order), each once
}
```

Every object is exactly these fields: the Rust types refuse unknown and missing fields.

## The mock

The mock does not apply the shortcut rule, and its heard text contains no shortcut. It ports the learning rule exactly (`learnCandidates`, `learnTerms`, `rememberTerms`, `enforceTerms`, held to the core's tables by `tests/unit/mock.spec.ts`) over an in-memory learned list that starts empty with an empty glossary: Copy and Accept learn into it (Accept records no clipboard write) and sets `learned` and an undo list, its finish enforces the learned spellings, `undoLearn` restores the list, and New and Discard clear `learned`; it keeps no learning log. The mock's `partial` follows its heard segments, its `rawText` is the text before learned-spelling enforcement and is non-null whenever the phase is finished, and it applies no shortcut glyphs (its heard text contains none).

`src/lib/mock.ts` runs the core's state machine in the browser over a fake microphone and transcriber, deterministically. Segment N is heard as "This is part N of the dictation."; durations come from `Date.now()`, so Playwright's clock controls the recorded time. While recording it emits a synthetic, speech-like level every 50 ms, and stops on Pause, Done and Discard. ## The menu bar

A Scriber icon sits in the macOS menu bar beside the clock, from launch until Quit. Every decision it makes is in `crates/scriber-core/src/menubar.rs`, with no I/O and no port; `src-tauri` only applies them.

**The menu.** Six items, in this order, rebuilt from `menubar::items(phase)` whenever the phase changes, so the flags are live:

| Item | id | Enabled in |
|---|---|---|
| Show Scriber | `show` | every phase |
| Record | `record` | idle, ready, finished |
| Pause | `pause` | recording |
| Done | `done` | recording, paused |
| Discard | `discard` | ready, recording, paused, finished, failed |
| Quit | `quit` | every phase |

Record is enabled in idle and finished as well as ready because it calls `Engine::record`, which applies New first from those two phases. A separator follows Show Scriber; the items carry no keyboard accelerators, because the shortcut is shown and changed in Settings only. A click runs on a `scriber-tray` thread (every engine method takes the session lock, and Record opens the microphone): Show Scriber reveals the window, Quit exits (the engine shuts down on `RunEvent::Exit`), Record calls `record()`, Pause, Done and Discard call `act(..)`, and an id the menu did not make is logged as `"outcome":"unknown"`. The tray and the menu catch up through the `Event::State` the engine emits.

**The global toggle.** One shortcut, ⌥⌘D by default, registered from Rust through the global-shortcut plugin and changeable in Settings (`toggle_shortcut`, in Scriber's canonical form: `+`-joined tokens, zero to four of `Ctrl`, `Opt`, `Shift`, `Cmd` with no repeats, then one key -- `A`..`Z`, `F1`..`F19`, `Space`, `Tab`, `Return` or `Escape` -- with at least one of `Opt` or `Cmd`). `menubar::accelerator` turns it into the plugin's `Alt+Super+KeyD`. The plugin reports Released as well as Pressed, so the handler acts on Pressed only; it then clones the engine onto a `scriber-tray` thread and calls `toggle()`, whose table is:

| Phase | Press |
|---|---|
| idle, ready, finished | record (New first, from idle and finished) |
| recording | Done |
| paused | Resume |
| transcribing, failed | nothing |

Paused resumes because Pause can be pressed in the window or in the menu, and the next press of the hotkey continues that session; transcribing and failed do nothing because Done has already been sent and a failed session is retried or discarded from the window. A press after `shutdown()` answers `ShutDown` in every phase. After a successful `settings_set` the old chord is removed (`unregister_all()`) and the new one registered before the command answers, so a changed shortcut works without a relaunch; each attempt writes a `shortcut` log line, so a registration that fails is silent in the UI but never in the log, and dictation from the window keeps working. ⌥⌘D is also macOS's own Dock hide/show chord, which is exactly why Settings can change it.

**Lifecycle.** Closing the window hides it (`prevent_close`, then hide), and the app keeps running with no Dock icon (`Accessory` activation policy) when only the menu bar is left; the Dock icon and app menu come back (`Regular`) whenever the window is shown. The one show path -- `reveal` -- is shared by the tray's Show Scriber, a second launch (the single-instance plugin) and `RunEvent::Reopen` on macOS, so a second launch from Finder brings the window back rather than leaving an icon-only app. Quit in the menu calls `app.exit(0)`, so `RunEvent::Exit` still shuts the engine down and `scripts/exit-check.sh` still passes.

**The notification.** When the session transitions into finished while the window is hidden, one notification titled `Scriber` carries the snapshot's own `notice`: "Copied to the clipboard.", "No speech was heard. ...", the clipboard-failure sentence, or that sentence with the archive's keep-segments suffix. `menubar::notice(previous, &snapshot)` decides, so nothing is shown for the later finished snapshots the encode and summary jobs report, nothing for failed, and nothing while the window is visible. It is posted inside the same main-thread closure as the tray refresh, never from the job thread that holds the session lock; visibility comes from the managed `Shown`, which the window-event handler sets. Every decision writes one `notify` log line.

**The icon.** `icons/tray-template.png` (22 by 22, black and alpha only, drawn as a template so macOS tints it for light and dark menu bars) while not recording, and `icons/tray-recording.png` (22 by 22, the light theme's `--recording` red, #d0103a) while recording; `menubar::icon(phase)` decides, and the shell swaps when `icon(previous) != icon(now)`. Both are rendered from `icon-source/tray.svg` and `icon-source/tray-recording.svg` and enter the binary through `include_bytes!`, so the bundle's icon list is untouched.

**The Mac check.** Open the app, close the window: the menu-bar icon stays and the Dock icon goes. Press ⌥⌘D twice: the first press starts recording and the icon turns red, the second finishes, and with the window hidden the copy notification appears (allow the notification permission prompt the first time). Note that ⌥⌘D is macOS's own Dock chord; change it in Settings and see the new chord work without a relaunch. Watch the menu's items enable and disable as the phase changes, use Show Scriber to bring the window back, Quit from the menu, then run `bash scripts/exit-check.sh`.

## Bundle

`src-tauri/Info.plist` (merged into the bundle's) carries `NSMicrophoneUsageDescription`, so macOS asks for the microphone the first time Record is clicked. `src-tauri/Entitlements.plist` grants `com.apple.security.device.audio-input`, which the hardened runtime requires for microphone input.
