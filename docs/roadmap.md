# Scriber roadmap

## Later

**Cleanup through a background `claude -p` session (work version).** On the 48 GB work Macs, keeping a local cleanup model loaded is a real memory cost, so the work version would offer Sonnet through a long-lived `claude -p` session as the cleanup backend: `--model sonnet --effort low --input-format stream-json --output-format stream-json`, with no tools (`--tools ""`), `--strict-mcp-config`, `--setting-sources project` run from an empty folder (so no CLAUDE.md or hooks load), `--disable-slash-commands` and `--no-session-persistence`, and the cleanup prompt as `--system-prompt`. A spot check on 2026-10-29 (10 test sentences, one run) gave 9/10 exact, about 1.1 s per cleanup with very little spread, 1.4 s to start the session, and about $0.0025 per cleanup; the local qwen3.8:27b-mlx gave 10/10 at about the same latency. Design notes from that run: put the glossary in the system prompt (cached once) and send only the transcript per turn, because a persistent session keeps every turn and resending the glossary grew the context by about 600 tokens per dictation; and restart the session every N dictations or when the glossary changes, so history never grows without bound. It would be another `Cleaner` adapter in the engine behind the existing port, with the same `cleanup::accept` guard.
