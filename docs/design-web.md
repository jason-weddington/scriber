# Scriber on the web

Status: **approved by Jason 2026-11-22, to build.** Requested by Jason: the full Scriber experience on his iPad, from a web app installed like any PWA, hosted on the Mac Studio, with the audio captured in the browser, transcribed on the Studio and the text copied to the iPad's clipboard. It is Scriber's own feature and is not coupled to Vortac in any way.

## Shape

```text
browser (Svelte UI, same code as the Mac app)
  ├─ mic ──▶ AudioWorklet ──▶ 16 kHz PCM16 binary frames ─┐
  └─ commands and events as JSON over one WebSocket ─────┤
                                                          ▼
              scriber-server (axum) ──▶ scriber-engine: StreamRecorder → whisper.cpp → cleanup → library
                                                          ▲
                              serves the built web app as static files from the same origin
```

- **One new crate, `crates/scriber-server`** in the root cargo workspace: a binary around `scriber-engine`. It owns no rules. It opens one `Engine` with `EngineConfig::recorder = Some(StreamRecorder)`, `clipboard: None` and `library: true`, serves the web build as static files, and exposes one WebSocket at `/ws`. Only this crate may use tokio and axum; `scripts/check-architecture.sh` keeps them out of the core and the engine.
- **The web app is the existing Svelte app**, built a second way (`VITE_SCRIBER_BACKEND=web`, script `pnpm build:web`, output `apps/desktop/dist-web`). Only `bridge.ts` knows which backend it talks to (Tauri, the mock, or the server); it may import a sibling `bridge-web.ts`. No `@tauri-apps` import appears anywhere else and the production web bundle carries no mock.
- **No global shortcut, no menu bar.** Everything else is the same screens, states and in-app keys: Space is Record, Pause and Resume, Return is Done, ⌘N is New (keydown handlers that already exist).

## Server

- **Settings (env, all optional except the token):** `SCRIBER_BIND` (default `127.0.0.1:8742`), `SCRIBER_TOKEN` (the shared secret; the server refuses to start without it unless `SCRIBER_ALLOW_NO_TOKEN=1`, for local development; a non-empty `SCRIBER_TOKEN` takes precedence over `SCRIBER_ALLOW_NO_TOKEN=1`), `SCRIBER_DATA` (the engine's data folder; default `$HOME/Library/Application Support/com.jasonweddington.scriber-server`, deliberately not the Mac app's folder, so the two never write the same library), `SCRIBER_MODEL_FOLDER` (optional startup-only override; must be an absolute path, persisted into `settings.json` via `DataDir` and `settings::load`/`save` before `Engine::open` while preserving every other saved setting, failing startup on save error; `settings_set` can change it in-session and a restart without `SCRIBER_MODEL_FOLDER` keeps the last saved folder; set it to the Mac app's models folder to share the 1.6 GB file, and the engine downloads the model there with `ModelSource::Download` when missing) and `SCRIBER_WEB_DIR` (the static files; default `apps/desktop/dist-web` relative to the working directory).
- **Lifecycle and shutdown.** The server binds its TCP listener before persisting `SCRIBER_MODEL_FOLDER` and opening one `Engine` with `EngineConfig::recorder = Some(StreamRecorder)`, `clipboard: None` and `library: true`. On `Ctrl-C` (`SIGINT`), Unix `SIGTERM` or a serving error after open, it stops admissions, closes and joins all tracked WebSocket tasks so in-flight RPCs and PCM pushes settle, and runs `Engine::shutdown()` off runtime workers (retaining any active recording's audio and unloading the speech model).
- **One engine, one session.** Every connection sees the same session and receives the same events. Audio is accepted only from the connection that issued the last `Record` or `Resume` transition into `recording`, so two devices cannot interleave audio.
- **`GET /healthz`** answers HTTP `200` with body `ok` and needs no token. Static files need no token (they contain no secret), are served strictly inside canonicalized `SCRIBER_WEB_DIR` (blocking path traversal and symlinks that escape the directory), and a missing web build returns `404` for static paths while keeping `/healthz` and `/ws` available.
- **Diagnostics.** Structured JSON-line diagnostics record generated connection IDs, fixed reason codes, bind/auth mode/static availability, startup failure stage, auth outcomes, ownership transitions, bounded per-connection audio counts, lag/writer/close outcomes and shutdown trigger plus `ShutdownReport` (`first`, `paused_recording`, `freed_model`). Tokens, raw frames, PCM bytes and transcript text are never logged.

## Protocol (`/ws`, JSON text frames plus binary audio)

- **Auth.** WebSocket control frames (`Ping`, `Pong`, `Close`) are handled at transport level. The first application message from the client must be `{"hello":{"token":"..."}}` (in `SCRIBER_ALLOW_NO_TOKEN=1` mode, clients still send `{"hello":{"token":""}}`). Any wrong or missing token, invalid hello shape, ordinary pre-hello RPC or pre-hello binary frame closes the socket with code `4401` before any engine work or event. The server answers `{"hello":{"version":"<crate version>","platform":"web"}}`.
- **Request and reply.** `{"id":<u32>,"call":"<name>","args":{...}}` is answered by exactly one `{"id":<same>,"ok":<value>}` or `{"id":<same|null>,"err":"<message>"}`. Argumentless calls (`dictation_state`, `library_list`, `settings_get`, `ollama_models`, `app_version`, `input_devices`, `window_fullscreen`, and the four unavailable calls) take `{}`; `dictation_act` takes `{"action":<Action>,"text":<string>}`; `library_get` and `library_copy` take `{"id":<string>}` (`library_copy` answers `ok: null` with no physical clipboard write); `settings_set` takes `{"settings":<Settings>}`. Nested `Snapshot`, `LibraryEntry`, `Settings`, `Action` and `Phase` shapes match `docs/design.md` verbatim, including raw `Snapshot.notice` text. `app_version` returns the same version string as `hello`; `input_devices` returns `{"default":"Browser microphone","others":[]}` (Web 2 maps `default` to the frontend's `defaultDevice`); `window_fullscreen` returns `true`. `vocabulary_open`, `learned_vocabulary_open`, `pick_vocabulary_file` and `pick_model_folder` answer `err` `"Not available in the web app."`.
- **Events.** `{"event":"dictation-changed","payload":<Snapshot>}` and `{"event":"dictation-level","payload":<number>}`, the same two events the Tauri app emits, to authenticated connections only. On auth the server subscribes before sampling state, sends `hello` then the bootstrap `dictation-changed` Snapshot, discards `dictation-level` events buffered at or before the bootstrap sample boundary and buffered Snapshots strictly older than bootstrap, preserves equal revisions and newer Snapshots, and leaves live-event versus RPC-reply order unconstrained. Each socket has one ordered writer and a bounded **64-event** subscriber queue that disconnects the subscriber on overflow so a stalled peer never blocks healthy peers or engine callbacks.
- **Audio.** Binary frames from client to server, little-endian PCM16, 16 kHz, mono, any even byte length up to 1 MiB (the browser sends 4,000 samples, 250 ms, per frame). The server pushes each frame with `StreamRecorder::push_pcm16` in arrival order. Frames outside phase `recording`, or from a connection that does not own the recording, are dropped (distinctly tracked as out-of-phase vs non-owner). Per-socket frames and calls are processed in arrival order and cross-socket phase-changing RPCs and PCM are coordinated, so audio sent before a `Done` call is in the capture when `Done` runs.
- **Errors and limits.** For authenticated valid transport, unknown calls, malformed JSON or envelopes, invalid args and odd-byte PCM return `err` and keep the socket open: the reply carries the valid `u32` `id` if recoverable and `id: null` (**uncorrelated**) otherwise (malformed JSON, missing/invalid `id`, odd-byte PCM). Incoming frames and reassembled messages (binary and text, single or fragmented) are capped at **1,048,576 bytes** (1 MiB inclusive) with bounded buffering; exceeding the limit closes the socket with code `1009` at transport level before application auth (`4401`), distinct from recoverable application errors. Closing the owning connection clears only that connection's lease and pauses nothing by itself: the session stays `recording` with no implicit reconnect grant until another connection recovers it with `Done` or `Discard`, and the status row says so (see Client).

## Client

- **Capture.** Capture uses `getUserMedia({audio: {channelCount: 1, echoCancellation: true, noiseSuppression: true}})`, started synchronously inside the click or keydown that asked for Record or Resume, because Safari only allows it from a gesture, and an AudioWorklet (a static `public/capture-worklet.js`; the CSP excludes `blob:` and inline worklets) that downmixes to mono and posts blocks to the main thread, which resamples to 16 kHz, converts to PCM16 and sends 250 ms frames. Tracks are stopped on Pause and Done, so the browser's microphone indicator goes off. The browser must have flushed its last frame before the Done call is sent.
- **Web 2 protocol adapters.** `bridge-web.ts` maps the server's `input_devices` wire shape (`{"default":"Browser microphone","others":[]}`) to the frontend's `InputDevices` (`{defaultDevice, others}`), and treats `{"id":null,"err":"..."}` replies as uncorrelated server errors rather than matching a pending RPC ID.
- **Clipboard.** The engine has no clipboard in the server and preserves raw `Snapshot.notice` verbatim in both RPC replies and `dictation-changed` events, so the browser writes the clipboard and owns notice display. On the Done action the web bridge immediately starts `navigator.clipboard.write([new ClipboardItem({"text/plain": <promise>})])` inside the gesture, where the promise resolves with the transcript when the finished Snapshot arrives (Safari accepts a promise there; a write after an `await` outside the gesture is refused). The web bridge suppresses or replaces the core's `"Copied to the clipboard."` notice on both RPC and event Snapshots until the browser clipboard write actually succeeds; if the write rejects, the status row shows the existing failure sentence `Could not copy to the clipboard: <reason>. Use Copy to try again.` and clicking Copy retries inside the click gesture. `library_copy` in the web build reads `library_get` (and may also call server `library_copy`, which answers `ok: null`) and writes the text in the click's gesture. **This is the one unproven behaviour. It cannot be tested in CI, so the build includes the fallback above, and Jason confirms the automatic copy on the iPad after the first deploy.**
- **Backend and connect screen.** The web build talks to the same origin it was served from. When that is not a Scriber server (the hello never arrives or the token is refused), a Connect screen asks for the server URL and token, keeps them in `localStorage` and retries; it is also reachable from Settings. This is what lets a GitHub user host the server anywhere. Browsers only expose the microphone on HTTPS or `localhost`, so a remote server needs TLS in front of it and the README says so.
- **Settings screen.** The toggle shortcut, pause shortcut, copy sound, vocabulary file, learned list, model folder and microphone controls are not shown in the web build. Every other control works as on the Mac. The window's left inset is the full-screen one, since a PWA has no traffic lights.
- **PWA.** `manifest.webmanifest` (name Scriber, `display: standalone`, theme and background colours from the app, the Scriber icon at 192 and 512 px, maskable variants), the Apple touch icon (180 px), the `apple-mobile-web-app-*` meta tags and a viewport that disables zoom. There is no service worker: installing needs none and the app is useless offline.
- **Owner reconnects.** When the socket drops and reconnects the page requests state and rebinds; a recording that lost its audio connection stays in `recording` and shows "Connection lost. Press Done to finish or Discard to start over." in the status row (a reserved row, no layout shift).

## Not here

- Authentication beyond one shared token, multiple users, or more than one concurrent session.
- Editing the vocabulary file from the browser (the learned words still work on the server).
- A service worker, offline use, or push notifications.
- Anything specific to this lab: the host name, TLS, the reverse proxy, the launchd job and the token value live in `~/git/homelab-ops`, not in this repository.

## Tests

- `crates/scriber-server` is tested in process over real loopback WebSockets with ephemeral ports, temporary data and static fixtures, `Engine::with_adapters` with local fakes (`src/tests/fakes.rs`) and a real `StreamRecorder` wired to `Engine`'s `level_sink`, plus a loopback HTTP `GET /api/tags` stub (no mic, real speech model, Ollama or `afconvert`). It covers config/auth/model-folder persistence, bind-before-open and shutdown lifecycle, static containment and symlinks, hello/4401, request/reply fixtures, library and Ollama calls, uncorrelated errors, bootstrap event ordering, 64-event lag disconnect, blocking RPC non-interference, ownership/disconnect recovery, exact ordered PCM16 through split and `Done`, 1 MiB / `1009` limits, and sanitized structured diagnostics.
- `crates/scriber-server` is included in the root workspace's 100% Rust line coverage floor and `.cargo/mutants.toml` release mutation scope (`src/**/*.rs` excluding `src/tests*`), with zero survivors allowed. See `scripts/gate.sh` and `docs/quality-gates.md`.
- The web build is tested in Playwright against a small Node stand-in for the server that speaks this protocol (`apps/desktop/tests/e2e`), with a fake microphone; the real clipboard behaviour is the iPad check above.
