# Scriber on the web

Status: **approved by Jason 2026-11-22, to build.** Requested by Jason: the full Scriber experience on his iPad, from a web app installed like any PWA, hosted on the Mac Studio, with the audio captured in the browser, transcribed on the Studio and the text copied to the iPad's clipboard. It is Scriber's own feature and is not coupled to Vortac in any way.

## Shape

```text
browser (Svelte UI, same code as the Mac app)
  ├─ mic ──▶ AudioWorklet ──▶ 16 kHz PCM16 binary frames ─┐
  └─ commands and events as JSON over one WebSocket ─────┤
                                                          ▼
              scriber-server (axum) ──▶ scriber-engine: StreamRecorder → whisper.cpp → cleanup → library
                                                          ▲
                              serves the built web app as static files from the same origin
```

- **One new crate, `crates/scriber-server`** in the root cargo workspace: a binary around `scriber-engine`. It owns no rules. It opens one `Engine` with `EngineConfig::recorder = Some(StreamRecorder)`, `clipboard: None` and `library: true`, serves the web build as static files, and exposes one WebSocket at `/ws`. Only this crate may use tokio and axum; `scripts/check-architecture.sh` keeps them out of the core and the engine.
- **The web app is the existing Svelte app**, built a second way (`VITE_SCRIBER_BACKEND=web`, script `pnpm build:web`, output `apps/desktop/dist-web`). Only `bridge.ts` knows which backend it talks to (Tauri, the mock, or the server); it may import a sibling `bridge-web.ts`. No `@tauri-apps` import appears anywhere else and the production web bundle carries no mock.
- **No global shortcut, no menu bar.** Everything else is the same screens, states and in-app keys: Space is Record, Pause and Resume, Return is Done, ⌘N is New (keydown handlers that already exist).

## Server

- **Settings (env, all optional except the token):** `SCRIBER_BIND` (default `127.0.0.1:8742`), `SCRIBER_TOKEN` (the shared secret; the server refuses to start without it unless `SCRIBER_ALLOW_NO_TOKEN=1`, for local development; a non-empty `SCRIBER_TOKEN` takes precedence over `SCRIBER_ALLOW_NO_TOKEN=1`), `SCRIBER_DATA` (the engine's data folder; default `$HOME/Library/Application Support/com.jasonweddington.scriber-server`, deliberately not the Mac app's folder, so the two never write the same library), `SCRIBER_MODEL_FOLDER` (optional startup-only override; must be an absolute path, persisted into `settings.json` via `DataDir` and `settings::load`/`save` before `Engine::open` while preserving every other saved setting, failing startup on save error; `settings_set` can change it in-session and a restart without `SCRIBER_MODEL_FOLDER` keeps the last saved folder; set it to the Mac app's models folder to share the 1.6 GB file, and the engine downloads the model there with `ModelSource::Download` when missing) and `SCRIBER_WEB_DIR` (the static files; default `apps/desktop/dist-web` relative to the working directory).
- **Lifecycle and shutdown.** The server binds its TCP listener before persisting `SCRIBER_MODEL_FOLDER` and opening one `Engine` with `EngineConfig::recorder = Some(StreamRecorder)`, `clipboard: None` and `library: true`. On `Ctrl-C` (`SIGINT`), Unix `SIGTERM` or a serving error after open, it stops admissions, closes and joins all tracked WebSocket tasks so in-flight RPCs and PCM pushes settle, and runs `Engine::shutdown()` off runtime workers (retaining any active recording's audio and unloading the speech model).
- **One engine, one session.** Every connection sees the same session and receives the same events. Audio is accepted only from the connection that issued the last `Record` or `Resume` transition into `recording`, so two devices cannot interleave audio.
- **`GET /healthz`** answers HTTP `200` with body `ok` and needs no token. Static files need no token (they contain no secret), are served strictly inside canonicalized `SCRIBER_WEB_DIR` (blocking path traversal and symlinks that escape the directory), and a missing web build returns `404` for static paths while keeping `/healthz` and `/ws` available.
- **Diagnostics.** Structured JSON-line diagnostics record generated connection IDs, fixed reason codes, bind/auth mode/static availability, startup failure stage, auth outcomes, ownership transitions, bounded per-connection audio counts, lag/writer/close outcomes and shutdown trigger plus `ShutdownReport` (`first`, `paused_recording`, `freed_model`). Tokens, raw frames, PCM bytes and transcript text are never logged.

## Protocol (`/ws`, JSON text frames plus binary audio)

- **Auth.** WebSocket control frames (`Ping`, `Pong`, `Close`) are handled at transport level. The first application message from the client must be `{"hello":{"token":"..."}}` (in `SCRIBER_ALLOW_NO_TOKEN=1` mode, clients still send `{"hello":{"token":""}}`). Any wrong or missing token, invalid hello shape, ordinary pre-hello RPC or pre-hello binary frame closes the socket with code `4401` before any engine work or event. The server answers `{"hello":{"version":"<crate version>","platform":"web"}}`.
- **Request and reply.** `{"id":<u32>,"call":"<name>","args":{...}}` is answered by exactly one `{"id":<same>,"ok":<value>}` or `{"id":<same|null>,"err":"<message>"}`. Argumentless calls (`dictation_state`, `library_list`, `settings_get`, `ollama_models`, `app_version`, `input_devices`, `window_fullscreen`, and the four unavailable calls) take `{}`; `dictation_act` takes `{"action":<Action>,"text":<string>}`; `library_get` and `library_copy` take `{"id":<string>}` (`library_copy` answers `ok: null` with no physical clipboard write); `settings_set` takes `{"settings":<Settings>}`. Nested `Snapshot`, `LibraryEntry`, `Settings`, `Action` and `Phase` shapes match `docs/design.md` verbatim, including raw `Snapshot.notice` text. `app_version` returns the same version string as `hello`; `input_devices` returns `{"default":"Browser microphone","others":[]}` (Web 2 maps `default` to the frontend's `defaultDevice`); `window_fullscreen` returns `true`. `vocabulary_open`, `learned_vocabulary_open`, `pick_vocabulary_file` and `pick_model_folder` answer `err` `"Not available in the web app."`.
- **Events.** `{"event":"dictation-changed","payload":<Snapshot>}` and `{"event":"dictation-level","payload":<number>}`, the same two events the Tauri app emits, to authenticated connections only. On auth the server subscribes before sampling state, sends `hello` then the bootstrap `dictation-changed` Snapshot, discards `dictation-level` events buffered at or before the bootstrap sample boundary and buffered Snapshots strictly older than bootstrap, preserves equal revisions and newer Snapshots, and leaves live-event versus RPC-reply order unconstrained. Each socket has one ordered writer and a bounded **64-event** subscriber queue that disconnects the subscriber on overflow so a stalled peer never blocks healthy peers or engine callbacks.
- **Audio.** Binary frames from client to server, little-endian PCM16, 16 kHz, mono, any even byte length up to 1 MiB (the browser sends 4,000 samples, 250 ms, per frame). The server pushes each frame with `StreamRecorder::push_pcm16` in arrival order. Frames outside phase `recording`, or from a connection that does not own the recording, are dropped (distinctly tracked as out-of-phase vs non-owner). Per-socket frames and calls are processed in arrival order and cross-socket phase-changing RPCs and PCM are coordinated, so audio sent before a `Done` call is in the capture when `Done` runs.
- **Errors and limits.** For authenticated valid transport, unknown calls, malformed JSON or envelopes, invalid args and odd-byte PCM return `err` and keep the socket open: the reply carries the valid `u32` `id` if recoverable and `id: null` (**uncorrelated**) otherwise (malformed JSON, missing/invalid `id`, odd-byte PCM). Incoming frames and reassembled messages (binary and text, single or fragmented) are capped at **1,048,576 bytes** (1 MiB inclusive) with bounded buffering; exceeding the limit closes the socket with code `1009` at transport level before application auth (`4401`), distinct from recoverable application errors. Closing the owning connection clears only that connection's lease and pauses nothing by itself: the session stays `recording` with no implicit reconnect grant until another connection recovers it with `Done` or `Discard`, and the status row says so (see Client).

## Client

- **Build and backend selection.** `pnpm build:web` in `apps/desktop` sets `VITE_SCRIBER_BACKEND=web` and emits `apps/desktop/dist-web` including `capture-worklet.js`, with no test source maps in release output (`vite.config.ts` emits source maps only for the instrumented test build and fails the build if the emitted JS module graph is empty or includes `src/lib/mock.ts`). In the web build `bridge.ts` delegates to `bridge-web.ts`, marks `<html>` with `data-bridge="web"` and never attaches `window.__mockBridge`; all existing `bridge.ts` exports keep their signatures and `@tauri-apps/*` imports stay confined to `bridge.ts`.
- **Connection lifecycle and configuration.** `bridge-web.ts` opens one same-origin `/ws` socket per page (`ws:` or `wss:` matching the origin scheme), sends the token only in the initial `hello` frame (empty token `""` by default for local development), and waits for a valid `{"hello":{"version":"...","platform":"web"}}` before dispatching calls or audio. `configureWebConnection({endpoint, token})` is exported via `bridge.ts` for Web 3, storing normalized origin and token in `localStorage` keys `scriber.web.endpoint` and `scriber.web.token` with an in-memory fallback when storage fails, and immediately retiring/rebinding the socket. Default deadlines are **5 s** for `hello`, **1 s** between transient reconnect attempts and **15 s** per RPC. Code `4401` refuses authentication without automatic retry until an explicit retry or `configureWebConnection`, and connection errors never expose tokens or payloads. Retiring a generation immediately rejects pending calls, stops capture, cancels pending Done clipboard association, ignores retired socket frames and never replays calls or audio.
- **Web 2 protocol adapters.** `bridge-web.ts` allocates unique in-flight `u32` IDs, handles out-of-order replies including falsy `ok` values, maps `input_devices` (`{"default":"Browser microphone","others":[]}`) to `{defaultDevice, others}`, returns `true` for `window_fullscreen` with a safe no-op `onFullscreenChanged` unsubscribe, rejects the four Mac-only calls with `"Not available in the web app."`, and treats `{"id":null,"err":"..."}` as uncorrelated server errors.
- **Capture (`browser-capture.ts`, `pcm16.ts`, `public/capture-worklet.js`).** On `Record` or `Resume`, `getUserMedia({audio: {channelCount: 1, echoCancellation: true, noiseSuppression: true}})` and `AudioContext` activation start synchronously inside the click or keydown gesture before any `await`. Setup loads the static `/capture-worklet.js` (CSP-compatible without `blob:` or `'unsafe-inline'`), connects `MediaStreamAudioSourceNode -> AudioWorkletNode -> zero-gain -> destination`, prepares before RPC dispatch, and arms binary transmission only after the local `Record`/`Resume` reply succeeds in phase `recording`. The worklet downmixes to mono and acknowledges `{type: "drain", id}` in port order; `pcm16.ts` performs block-boundary-invariant streaming linear resampling to 16 kHz mono, clipping and signed little-endian PCM16 framing in 4,000-sample (250 ms, 8,000-byte) full frames plus a nonempty short tail. `Pause` and `Done` drain the worklet (default **1 s** timeout; missing ack cleans up and fails recoverably without dispatching the action) and flush full frames plus tail before sending the action JSON; `Discard`, remote departure from `recording`, disconnect, denial, setup failure and remote interruption during pending setup all stop tracks (including late-resolving streams), disconnect nodes and close the `AudioContext`.
- **Clipboard.** The engine has no clipboard in the server and preserves raw `Snapshot.notice` verbatim, so the browser owns clipboard writes and notice projection.
  - **Done auto-copy:** Starts `navigator.clipboard.write([new ClipboardItem({"text/plain": <promise>})])` synchronously inside the `Done` click or keydown gesture before any `await`, gated on the matching successful `Done` reply on the active generation. Resolves from a directly `finished` reply or a contiguous, consistent revision sequence from `transcribing` to the first non-empty `finished` snapshot (including `scriber-core`'s atomic `+2` revision / `+1` `libraryRevision` finish-and-archive step), buffering early events and tolerating identical duplicates; cancels without writing on gaps, contradictory revisions, superseding phases, failure, empty text, disconnect or the **5 min** association timeout.
  - **Feedback projection:** Projected independently of `actionError` and raw `Snapshot`: hides the core's synthetic `"Copied to the clipboard."` prefix until local browser write succeeds, preserves archive suffixes, no-speech notices and learning feedback, and retains the local outcome across equal or later snapshots of that finish (including remote and `Retry` finishes). Early or late rejection shows `Could not copy to the clipboard: <reason>. Use Copy to try again.` and Copy retries inside the click gesture with the edited draft, sending `dictation_act("copy", draft)` for learning only after browser write succeeds and surfacing any learning RPC failure separately in `actionError`.
  - **Library copy:** `libraryCopy(id)` starts `navigator.clipboard.write` synchronously in the click gesture with a promised `Blob` populated by `library_get` (never invoking `library_copy` over the wire), reporting success only after write completion and surfacing missing-entry or write errors in `.status-row`.
- **Rebind and former-owner reconnects.** On every authenticated rebind, `App.svelte` clears `loadError`, invalidates earlier-generation async completions, resets both `revision` and `libraryRevision` baselines before resuming normal ordering, and refreshes `dictation_state`, `settings_get`, `app_version` and `library_list`. If the tab owned a recording when its socket dropped and reconnects while the session is still `recording`, `.status-row` displays `"Connection lost. Press Done to finish or Discard to start over."` without restarting the microphone until the user recovers via `Done` or `Discard` (or another client changes phase).
- **Connect screen, Settings screen and PWA.**
  - **PWA metadata and icons (web build only).** `vite.config.ts` transforms `index.html` only when `VITE_SCRIBER_BACKEND=web`: it sets the single viewport meta tag to `width=device-width, initial-scale=1.0, user-scalable=no` and injects `apple-mobile-web-app-capable=yes`, `apple-mobile-web-app-title=Scriber`, `<link rel="apple-touch-icon" href="/apple-touch-icon.png">` (180×180), and `<link rel="manifest" href="/manifest.webmanifest">`. Desktop and mock builds keep the original viewport and no install tags. `apps/desktop/public/manifest.webmanifest` declares `name`/`short_name` `"Scriber"`, `start_url`/`scope` `"/"`, `display` `"standalone"`, and four root-relative PNG icons derived from `apps/desktop/src-tauri/icons/icon.png` (`icon-192.png` and `icon-512.png` with `purpose: "any"`, plus `icon-maskable-192.png` and `icon-maskable-512.png` with opaque backgrounds, `purpose: "maskable"`, and foreground artwork inside the 40% safe radius). No service worker is registered.
  - **Web Settings and browser microphone indicator.** When `isWebBackend()` is true, Settings hides both global shortcuts, copy sound, vocabulary file, learned vocabulary file, speech model folder and input-device controls, while preserving silence splitting, both Ollama switches and model selectors, version display and full-`Settings` round-trip writes (keeping hidden fields intact), and adds a Server row with a **Connect** button. The recorder shows a non-interactive `Browser microphone` indicator without a device picker.
  - **Connection attempt state and Connect modal.** `WebUiState.connection` publishes a replayable, sanitized connection attempt state (`idle`, `connecting`, `authenticated`, or `failed` with active `generation`, `effectiveOrigin`, `reason`, `priorAuth` and fixed `failureCode`), guarding every socket callback and timer by active generation/socket identity so retired sockets cannot send `hello`, mutate refusal/ownership or trigger refresh. The native `<dialog>` Connect modal (`ConnectPanel.svelte`) offers labelled `Server URL` and masked `Shared token` fields with `Connect`, `Cancel` and (when unauthenticated) `Try again` actions and a reserved `.status-row` reporting only fixed messages (`Enter a valid server URL.`, `Authentication refused.`, or `Could not connect to the Scriber server.`). Opening pre-fills the effective origin and leaves the token blank; blank URL uses page origin, blank token submits empty, `Try again` retries the currently configured credentials, and `normalizeOrigin` rejects malformed/unsupported URLs (such as `ftp://example.invalid`) and insecure non-loopback HTTP/WS origins from HTTPS pages before any state or storage mutation. Connect opens automatically on any active `4401` (before or after prior auth) and on startup or explicit save/retry handshake failures (`hello_timeout`, `invalid_hello`, `closed_before_hello`, pre-hello `1009`, or synchronous socket construction failure), while background reconnects after prior auth suppress Connect and keep transient retry and former-owner recovery. Only one native modal is open at a time (Settings closes explicitly before Connect opens, manual cancel/Escape reopens Settings with focus on `Connect`, auto recovery interrupts Settings and returns focus to the persistent recovery/Settings trigger on dismissal, active auth dismisses automatic or submitted Connect while background auth leaves untouched manual Connect open, dismissals clear the token draft, and recorder shortcuts stay suspended). Changing the normalized origin immediately invalidates in-flight operations, clears prior server data/selection/feedback, resets former-owner projection and disables settings writes until the new server's `settings_get` completes. Browsers only expose the microphone and async clipboard on HTTPS or `localhost`, so a remote server needs TLS in front of it.

## Not here

- Authentication beyond one shared token, multiple users, or more than one concurrent session.
- Editing the vocabulary file from the browser (the learned words still work on the server).
- A service worker, offline use, or push notifications.
- Anything specific to this lab: the host name, TLS, the reverse proxy, the launchd job and the token value live in `~/git/homelab-ops`, not in this repository.
